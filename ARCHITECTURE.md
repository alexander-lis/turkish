# Архитектура

Справочник состоит из трёх частей. Контент — файлы в `content/`. Сервер (`backend/`, пакет `turkish_grammar`) проверяет контент и отдаёт его через API только для чтения. Интерфейс (`frontend/`) показывает контент в браузере. Термины определены в [GLOSSARY.md](GLOSSARY.md), формат файлов контента описан в [content/README.md](content/README.md).

Базы данных нет: контент хранится только в файлах репозитория. Сервер читает его один раз при старте и держит в памяти.

```
 content/ ─▶ content.loader ─▶ Catalog ─┬────────────────────────────────────────▶ api.routes ─▶ GET /api/* ─▶ frontend/ (React)
             (files, article,           ├─▶ content.graph ─▶ TopicGraph ─────────┤  (api.schemas)
              gloss, markup)            ├─▶ content.search_index ─▶ SearchTopic ─┘
                   │                    ├─▶ content.summary ─▶ cli summarize-content
                   │                    └─▶ wordforms.check ─▶ cli check-words
                   │                          ├─ extraction
                   │                          └─ analyzer ─▶ zeyrek
                   └─ ошибки ─▶ InvalidContentError ─▶ cli check-content; сервер не стартует

 api.schemas ─▶ cli export-openapi ─▶ openapi.json ─▶ openapi-typescript ─▶ frontend/src/api/schema.d.ts
```

## Слои сервера

`backend/src/turkish_grammar/` делится на подпакеты. Модуль импортирует только из слоёв ниже своего (через слой — можно), внутри слоя импорты свободны. Это проверяет контракт «Слои» для `lint-imports` в `backend/pyproject.toml`; он `exhaustive`, так что новый подпакет или модуль верхнего уровня нужно поставить в слой.

| Слой | Пакет | Что в нём | Чего в нём нет |
|---|---|---|---|
| вход | `cli`, `api/` | команды argparse и печать; приложение FastAPI, маршруты и схемы ответов | правил контента |
| проверки | `wordforms/` | проверка словоформ: какие слова проверять и что о них говорит анализатор | правил формата файлов |
| контент | `content/` | предметная модель, чтение файлов и все правила их формата и связей | HTTP, печати, анализатора |
| настройки | `settings` | откуда читать контент | всего остального |

`api` и `wordforms` друг о друге не знают. `cli` — единственный модуль, который собирает их вместе.

Предметная модель — `content.model`: замороженные dataclass без ввода-вывода (`Topic`, `Example`, `Contrast`, `Catalog` и т.д.). `content.graph` и `content.search_index` — производные от неё: граф тем и поисковый индекс вычисляются из `Catalog` и в файлах не хранятся. Pydantic-модели живут на границах: `content.files` описывает форму файлов, `api.schemas` — форму ответов API. Модель из файлов строит `content.loader`, ответы из модели — `api.routes` через `model_validate`.

zeyrek — зависимость разработки. Его импортирует только `wordforms.analyzer`, и только при первом обращении: серверу анализатор не нужен.

## Карта кода

У каждого модуля есть строка здесь и докстринг, который называет его роль не длиннее чем в трёх строках; подробности живут здесь или в спецификации. `backend/tests/test_architecture.py` проверяет и то и другое: модуль без строки, строку без модуля, модуль без докстринга или со слишком длинным. Докстринг пакета называет роль слоя, а не его модули; `__init__.py` получает строку, только если в нём есть функции или классы.

| Пакет | Модуль | За что отвечает |
|---|---|---|
| | `settings` | `Settings`: каталог контента из `CONTENT_DIR`, по умолчанию `content/` в корне; `REPO_ROOT`. |
| | `cli` | Команды `turkish-grammar`: `check-content`, `check-words`, `summarize-content`, `export-openapi`. Анализатор импортирует внутри `check-words`. |
| `api` | `app` | `create_app`: контент загружается в `lifespan`, а не при сборке, поэтому описание API доступно и без контента; там же из каталога строятся граф тем и поисковый индекс. С невалидным контентом сервер не стартует. Имя операции в OpenAPI — имя функции. |
| | `routes` | Шесть `GET` под `/api`: `topics`, `sections`, `topics/{id}`, `graph`, `search-index`, `notation`. Только читают `Catalog`, `TopicGraph` и поисковый индекс из `app.state` и переводят их в схемы ответов; неизвестная тема — 404. |
| | `schemas` | Pydantic-схемы ответов; из них строится OpenAPI, а из него — типы интерфейса. |
| `content` | `model` | Предметная модель: `Level`, `Topic` (обзор — тема с `members`), `Example`, `GlossedWord`, `Section`, `Contrast`, `Abbreviation`, `KnownWord`, `Catalog`; `ARTICLE_TEMPLATE` — блоки статьи в их порядке. |
| | `files` | Форма файлов контента — метаданных темы, примера, раздела, различения, обозначения, известного слова (Pydantic, лишние поля запрещены) — и перевод ошибок Pydantic в сообщения автору. |
| | `loader` | `load_catalog`: два прохода — каждый файл сам по себе, затем связи (ссылки, обзоры, различения, учебный маршрут, уровни, разделы, обозначения); собирает все ошибки сразу. Обзор и различение сверяет со ссылками `topic:<id>` в статьях. `load_known_words`. Имена файлов контента — константы здесь. |
| | `graph` | `build_graph`: граф тем из каталога — связи трёх видов (пререквизит, тема обзора, связанная тема) в порядке учебного маршрута и обратные индексы темы: её обзоры, различения и связанные темы без повторов. Здесь живёт правило «связанная тема уступает более определённой связи». |
| | `search_index` | `build_search_index`: поисковый индекс из каталога — по записи на тему в порядке учебного маршрута: то же, что в списке тем, название раздела, текст блоков статьи без разметки и тексты примеров. У заглушки блоков и примеров нет. Все строки — в NFC: поиск в браузере сравнивает символ с символом. |
| | `article` | Разбор `topic.md`: метаданные, блоки по шаблону, ссылки на темы. Через markdown-it-py, а не по строкам: заголовок внутри блока кода не должен стать заголовком блока статьи, а ссылки нужны вместе с адресами. В HTML текст не превращает — это делает интерфейс. `plain_lines` — текст блока без разметки для поискового индекса: по строке на абзац, пункт списка, подзаголовок и строку таблицы. |
| | `gloss` | Разбор по морфемам: строки `morphemes` и `gloss` → слова и морфемы; сверка с текстом примера. |
| | `markup` | Выделение звёздочками в тексте примера → отрезки текста. |
| | `turkish` | Турецкий нижний регистр (I → ı, İ → i) и нормализация текста для сверки. |
| | `errors` | `ContentIssue`, `InvalidContentError` со всеми ошибками, `format_issues` — отчёт для человека. |
| | `summary` | Сводка наполнения: темы и заглушки по уровням, примеры у написанных тем. |
| `wordforms` | `extraction` | Какие слова контента турецкие: в поле `tr` примера — каждое слово; в русских текстах (название, суть, статья, название различения, вводный текст к обозначениям) — слово, набранное латиницей. Ищет и смешение алфавитов в одном слове. |
| | `analyzer` | Единственный модуль, который знает о zeyrek: `is_recognized`. zeyrek импортируется при первом обращении, а не вместе с модулем: серверу он не нужен. |
| | `check` | `check_word_forms`: слова, которых не признаёт анализатор и которых нет в списке известных слов; проверка самого списка. |

## Потоки

**Старт сервера** (`mise run dev:backend`). uvicorn поднимает `api.app:app` → `lifespan` вызывает `load_catalog`, затем `build_graph` и `build_search_index` → `Catalog`, `TopicGraph` и поисковый индекс кладутся в `app.state`. Статьи разбираются в текст без разметки один раз, здесь, а не на каждый запрос индекса. Ошибка контента — отчёт в лог, сервер не стартует. В разработке uvicorn перезапускается при правке кода и файлов `content/`.

**Проверка контента** (`mise run content:check`). `cli check-content` → `load_catalog` → все ошибки с файлом и причиной, код выхода 1; без ошибок — число тем и заглушек.

**Проверка словоформ** (`mise run content:words`). Сначала та же загрузка каталога. Затем `wordforms.extraction.find_words` собирает слова, `analyzer.is_recognized` проверяет каждое, `check` вычитает известные слова из `content/known-words.yaml`. На старт сервера не влияет. Переход с zeyrek на Zemberek запланирован; код, который знает об анализаторе, — только `analyzer`.

**Типы интерфейса** (`mise run gen:api`). `cli export-openapi` пишет `frontend/openapi.json` (в git не хранится), openapi-typescript генерирует `frontend/src/api/schema.d.ts` (хранится в git, руками не правится). `gen:api:check` входит в `mise run check` и падает, если сохранённый файл отстал от схем.

## Интерфейс

`frontend/` — Vite, React, TypeScript, Tailwind, TanStack Query, react-router. Карта тем добавляет две зависимости: `@xyflow/react` (React Flow — холст с перемещением, масштабом и узлами-компонентами) и `d3-hierarchy` (раскладка дерева). В разработке Vite проксирует `/api` на `127.0.0.1:8000`.

- `src/api/client.ts` — единственный модуль, который ходит в сеть (openapi-fetch по `schema.d.ts`); `ApiError`, `isNotFound`.
- `src/api/types.ts` — псевдонимы `components["schemas"]`; своих типов ответов в интерфейсе нет.
- `src/api/queries.ts` — `queryOptions`: ключи и загрузчики. Карте тем нужны два запроса: граф тем (`graphQuery`, `GET /api/graph`) — из него она берёт и сами темы в порядке учебного маршрута — и разделы (`sectionsQuery`). Список тем `GET /api/topics` интерфейс не запрашивает. Поиску нужен поисковый индекс (`searchIndexQuery`, `GET /api/search-index`): запрос включается, когда окно поиска открыто, и дальше индекс живёт в кеше — повторное открытие окна и переход между страницами его не перезапрашивают.
- `src/lib/` — чистые функции: адреса страниц, окна темы и блоков темы (`site.ts`), шаблон страницы темы (`template.ts`, `TEMPLATE`: семь блоков в их порядке и заголовки). Четыре блока — текст статьи с сервера; «Примеры», «Не путать» и «Связанные темы» страница собирает сама из примеров и связей темы. Новый вид блока на сервере ломает компиляцию, пока ему не дадут место.
- `src/lib/map*.ts` — логика карты тем, чистые функции без холста:
  - `mapTree.ts` — `buildMapTree`: дерево видимых узлов по включённым уровням и развёрнутым разделам. Родитель темы — первый по учебному маршруту видимый обзор её раздела, в который она входит, иначе раздел; связи «тема обзора», не ставшие веткой, возвращаются отдельно.
  - `mapLayout.ts` — `splitSections` делит разделы между правой и левой сторонами по полному числу тем, один раз; `layoutMap` раскладывает каждую сторону `tree()` из `d3-hierarchy` с фиксированным шагом и отражает левую по горизонтали. Узел раздела выше узла темы — его название занимает до трёх строк, — поэтому соседние разделы стоят дальше друг от друга, чем темы, с тем же просветом.
  - `mapLinks.ts` — `crossLines`: перекрёстные линии между видимыми темами (связи с обзорами вне веток, включённые слои, все связи темы, которая выбрана или на узел которой навели; различение — линиями между каждой парой); `topicLinks`: связи темы по видам, в порядке маршрута, — из них окно темы берёт список «Нужна для» — и `linkedTopicIds`: темы, узлы которых рядом с выбранной не приглушаются.
  - `mapSettings.ts` — то, что карта хранит в `localStorage`, под двумя ключами. `topic-map-view` — настройки вида (уровни, слои, развёрнутые разделы): чтение с отбрасыванием неизвестного и испорченного, умолчания, переключение уровня, раскрытие темы. `topic-map-viewport` — положение карты (сдвиг и масштаб); испорченное или неполное значение отбрасывается целиком. Ключи разные, потому что от настроек зависит раскладка, а положение меняется при каждом сдвиге.
  - `mapFlow.ts` — раскладка и линии в виде узлов и линий React Flow: размеры, точки крепления, начертание, имена линий для программ чтения с экрана, приглушение узлов, не связанных с подсвеченной темой; `nodeFitsCanvas` — виден ли узел на холсте целиком. `mapStyle.ts` — тон уровня и начертание линии каждого вида, общие для холста и условных обозначений.
- `src/lib/search*.ts`, `affixFormula.ts` — правила поиска, чистые функции без React и DOM; поведение — в спецификации `topic-search`:
  - `searchFold.ts` — `foldText`: свёртка регистра и диакритики для сравнения, символ в символ. Поэтому место совпадения в свёрнутой строке то же, что в исходной, и фрагмент вырезается без пересчёта. `queryWords`: слова запроса — в NFC, свёрнутые, без дефисов по краям.
  - `affixFormula.ts` — `isAffixFormula` узнаёт формулу аффикса среди слов названия по правилу из `content/README.md`; `expandAffixFormula` разворачивает её в варианты: заглавная буква — каждый из её звуков, часть в скобках есть или её нет, косая черта перечисляет варианты. Строчные буквы не чередуются.
  - `search.ts` — `prepareIndex` сворачивает поисковый индекс один раз: слова названия вместе с вариантами формул, суть, строки примеров и блоков. `searchTopics` ищет по подготовленному: ступень слова запроса в теме (слово названия равно ему, начинается с него, содержит его; суть; пример; текст блока), ступень темы — худшая из ступеней слов, порядок — по ступени, затем по учебному маршруту; не больше двадцати тем и общее число найденных. Там же строка результата: название с выделенными совпадениями (в обычном слове — само вхождение, формула аффикса — целиком), место совпадения, фрагмент с выделением (длинная строка — окном вокруг первого совпадения по границам слов) и адрес — карта с темой в окне темы, открытом на блоке, если совпал пример или текст блока.
- `src/components/` — `Layout` (шапка: название справочника, кнопка поиска и ссылка «Карта тем» — других элементов навигации и списка тем в ней нет; со страницы темы название и ссылка ведут на карту к этой теме, `/?topic=<id>`, с остальных страниц — на `/`; у карты вид широкий: содержимое занимает всё место под шапкой без полей и прокрутки, у остальных страниц — колонка по центру), `TopicArticle` (содержимое темы по шаблону — одно для страницы темы и окна темы на карте), `topicHref.ts` (`TopicHrefContext` — куда ведёт ссылка на тему: по умолчанию на её страницу; его читают ссылки на темы в `TopicArticle` и ссылки `topic:<id>` в `ArticleMarkdown`), `ArticleMarkdown`, `ExampleCard`, `GlossView` (разбор по морфемам таблицей из двух строк), `AffixText` (запись аффикса без переноса), `TopicMarks` (`StubMark` — пометка «не написано» у ссылки на заглушку), `QueryView` (загрузка и ошибка; `Loading` — вращающееся кольцо по центру отведённого места, которое появляется с задержкой, чтобы быстрая загрузка не мелькала; его же показывает маршрут карты, пока грузится её код). Карта тем: `MapNodes` (узлы корня, раздела и темы — кнопка внутри узла, фокус получает она, а не обёртка React Flow), `MapEdges` (`ArcEdge` — линия между темами одного столбца: дуга, выгнутая наружу, тем сильнее, чем дальше темы друг от друга; путь считает `arcPath` из `mapFlow.ts`), `mapNodeActions.ts` (контекст: выбор темы, сворачивание раздела и подсветка связей темы, пока на её узле указатель мыши или фокус клавиатуры), `MapTopicDialog` (окно темы поверх карты: `TopicArticle` под `TopicHrefContext` с адресами карты, поэтому ссылки на темы открывают их в том же окне; открыв окно, само прокручивает к блоку из адреса — статью из кеша `TopicArticle` отрисовывает раньше, чем окно открылось, а в закрытом окне прокручивать нечего; сверх содержимого страницы — список «Нужна для», который карта берёт из графа, потому что в ответе о теме его нет; длинный список свёрнут под подписью с числом тем; действия «Развернуть» — ссылка на страницу темы — и «Закрыть»), `MapToolbar` (переключатели слоёв и уровней, «Показать всё», «Развернуть все»; на узком экране — сворачиваемый блок), `MapLegend` (условные обозначения).
- Окно поиска, `src/components/`, — три части, сверху вниз:

  ```
   Layout
     │
   SearchLauncher     кнопка в шапке, сочетание клавиш, открыто или закрыто
     │
   TopicSearch        запрос → индекс → searchTopics → строки тем; куда ведёт выбор
     │          ╲
   SearchDialog   lib/search.ts, searchFold.ts, affixFormula.ts
   окно, поле, список, клавиши, ARIA
  ```

  - `SearchLauncher` — кнопка поиска в шапке и сочетание Cmd+K или Ctrl+K; хранит только «окно открыто». Клавишу узнаёт по `event.code`, а не по `event.key`: при русской раскладке буква была бы другой. Сочетание переключает окно, действие браузера отменяется. Кнопка выглядит как поле с подсказкой сочетания (`⌘K` на macOS, `Ctrl K` на остальных, по `navigator.userAgent`); на широком экране она стоит по центру шапки, на узком от неё остаётся значок у ссылки «Карта тем».
  - `TopicSearch` — связка: хранит запрос и сбрасывает его, когда окно закрыто; запрашивает поисковый индекс и один раз готовит его (`prepareIndex`); на каждое изменение запроса зовёт `searchTopics` и превращает найденные темы в строки оболочки. Рисует строку темы: название, уровень, пометку «не написано» и место совпадения — раздел или фрагмент с подписью. Собирает состояния окна: подсказку при пустом запросе (виды запросов с примерами, которые подставляются в поле нажатием), загрузку, ошибку с повтором (через `QueryView`), «Ничего не найдено». Выбор строки открывает тему в окне темы на карте и закрывает окно поиска либо открывает её в новой вкладке и оставляет окно поиска открытым.
  - `SearchDialog` — оболочка: модальный `<dialog>`, поле запроса, список строк, клавиши и разметка «поле со списком» (`combobox`, `listbox`, `option`). На широком экране окно стоит по центру и не меняет высоту, чтобы поле не прыгало вместе со списком; на узком — прижато к верху. О темах, индексе, API и адресах тем она не знает. Строки получает данными, уже упорядоченными (`id`, `href` и то, что нужно для отрисовки), и сама их не фильтрует и не сортирует; выбранная строка — номер в списке, новый массив строк — выбрана первая. Строку оболочка оборачивает в ссылку по `href` из данных, поэтому нажатие с клавишей-модификатором и средней кнопкой открывает её браузер. Что значит выбор, решает тот, кто открыл окно: оболочка только зовёт `onSelect` с целью — та же вкладка или новая. Так оболочку можно переписать на библиотеке, не трогая правила поиска и связку с темами.
  - `useBackdropPress.ts` — общий хук модальных окон: нажатие на затемнение вокруг `<dialog>`. Им пользуются окно поиска и `MapTopicDialog`.
- `src/pages/` — `MapPage` (`/`, главная), `TopicPage` (`/topics/:id`), `NotationPage` (`/notation`; ссылка на неё — только в блоке «Примеры» темы с разбором), `NotFoundPage`. Маршруты собирает `src/AppRoutes.tsx`; старый адрес карты `/map` перенаправляется на `/` с той же строкой запроса. `TopicPage` добавляет к `TopicArticle` заголовок вкладки. `TopicArticle` открывается на блоке из адреса — и на странице темы (`/topics/<id>#block-<вид>`), и в окне темы на карте (`/?topic=<id>#block-<вид>`, его собирает `mapTopicBlockPath`, по нему ведёт строка поиска). Браузер к такому якорю сам не прокрутит — когда он обрабатывает адрес, тема ещё не загружена, — поэтому `TopicArticle` делает это после отрисовки темы и при каждом переходе (`scrollToBlock.ts`); заголовкам блоков дан отступ прокрутки на высоту шапки, в окне темы он меньше. В `TopicArticle` место темы на карте — пререквизиты, «Входит в обзор», «Темы обзора» — показывает один компонент `TopicLinks` в начале, а блок «Не путать» — `Contrasts`: название различения, остальные его темы и ссылка «Разбор», если различие разобрано не в этой теме. У заглушки вместо статьи сообщение, а блоки из связей остаются. Учебный маршрут в интерфейсе виден только здесь: переходами «Предыдущая тема» и «Следующая тема».
- `src/pages/MapPage.tsx` — карта тем: соединяет функции `src/lib/map*.ts` с React Flow, адресом и хранилищем. Выбранная тема живёт в адресе (`/?topic=<id>`), и это же значит «окно темы открыто»: закрытие окна убирает тему из адреса, а отдельного состояния «выбрана, но окно закрыто» нет. Переходы между темами в окне и закрытие кладут записи в историю, поэтому кнопка браузера «Назад» листает темы. Адрес главнее сохранённых настроек: тема из нового адреса раскрывает свой раздел и уровень, а если её узел не виден на холсте целиком, вид сдвигается к нему. Положение карты читается из хранилища один раз, при открытии страницы, и записывается после каждого сдвига, масштаба и анимации (`onMoveEnd`); вписывается в экран карта только тогда, когда сохранённого положения нет, и по действиям «Показать всё» и «Развернуть все» — с отступами под блок переключателей. Поэтому возврат со страницы темы обходится без своей истории: ссылка в шапке даёт тему, хранилище — место на карте. Связи темы карта показывает и без выбора: подсвечена выбранная тема, а пока выбора нет — та, на узел которой навели; выделение получает только выбранный узел. Окно темы — модальный `<dialog>`: неактивный фон, фокус внутри окна, закрытие по Escape и возврат фокуса на узел темы даёт браузер, а не свой код. Маршрут подключён через `React.lazy`, поэтому React Flow, `d3-hierarchy` и стили холста лежат в отдельном файле сборки: страница темы, открытая по прямой ссылке, их не грузит.

## Тесты

Сервер — pytest в `backend/tests/`, по подпакетам: `content/`, `api/`, `wordforms/`. Контент для тестов собирает `ContentBuilder` из `tests/support.py` во временной папке; настоящий `content/` тесты не читают, кроме `test_author_guide.py`, который прогоняет через проверку образцы из `content/README.md`. Тесты словоформ подставляют `FakeAnalyzer` вместо zeyrek. `test_architecture.py` не повторяет ни одного модуля: он разбирает модули через `ast` и сверяет их докстринги и карту кода в этом файле.

Интерфейс — Vitest и Testing Library рядом с кодом (`*.test.tsx`), сеть подменяет msw (`src/test/server.ts`), данные — `src/test/fixtures.ts` (там же тестовый граф тем и тестовый поисковый индекс с теми же темами). Холсту React Flow в jsdom нужны заглушки окружения — наблюдатель размеров, `DOMMatrixReadOnly`, размеры элементов, — окнам темы и поиска — `showModal` и `close` у `<dialog>`, а прокрутке к элементу — `scrollIntoView`; они в `src/test/setup.ts`, а `src/test/setup.test.tsx` проверяет, что с ними холст рисуется, окно открывается и закрывается, а прокрутка вызывается без ошибки. Логику карты проверяют модульные тесты `src/lib/map*.test.ts`; тесты `MapPage` проверяют только связку: узлы, выбор, окно темы, адрес, хранилище. Правила поиска проверяют модульные тесты `src/lib/searchFold.test.ts`, `affixFormula.test.ts` и `search.test.ts` по сценариям спецификации `topic-search`. Оболочку окна поиска `SearchDialog.test.tsx` проверяет на строках, которые не темы, и находит элементы по ролям `combobox`, `listbox` и `option`, а не по классам и структуре: тесты переживут замену оболочки. Связку — `TopicSearch.test.tsx` (состояния окна, вид строки, переход по выбору) и `SearchLauncher.test.tsx` (кнопка, сочетание клавиш, закрытие) на приложении целиком. Жесты, вид на узком экране, сама прокрутка и то, что в модальном окне делает браузер, — неактивный фон, фокус, Escape, окно поиска поверх окна темы — проверяются в браузере.
