# Архитектура

Справочник состоит из трёх частей. Контент — файлы в `content/`. Сервер (`backend/`, пакет `turkish_grammar`) проверяет контент и отдаёт его через API только для чтения. Интерфейс (`frontend/`) показывает контент в браузере. Термины определены в [GLOSSARY.md](GLOSSARY.md), формат файлов контента описан в [content/README.md](content/README.md).

Базы данных нет: контент хранится только в файлах репозитория. Сервер читает его один раз при старте и держит в памяти.

```
 content/ ─▶ content.loader ─▶ Catalog ─┬───────────────────────────────▶ api.routes ─▶ GET /api/* ─▶ frontend/ (React)
             (files, article,           ├─▶ content.graph ─▶ TopicGraph ─┘  (api.schemas)
              gloss, markup)            ├─▶ content.summary ─▶ cli summarize-content
                   │                    └─▶ wordforms.check ─▶ cli check-words
                   │                          ├─ extraction
                   │                          └─ analyzer ─▶ zeyrek
                   └─ ошибки ─▶ InvalidContentError ─▶ cli check-content; сервер не стартует

 api.schemas ─▶ cli export-openapi ─▶ openapi.json ─▶ openapi-typescript ─▶ frontend/src/api/schema.d.ts
```

## Слои сервера

`backend/src/turkish_grammar/` делится на подпакеты. Модуль импортирует только из слоёв ниже своего (через слой — можно), внутри слоя импорты свободны. Это проверяет контракт «Слои» для `lint-imports` в `backend/pyproject.toml`; он `exhaustive`, так что новый подпакет или модуль верхнего уровня нужно поставить в слой.

| Слой | Пакет | Что в нём | Чего в нём нет |
|---|---|---|---|
| вход | `cli`, `api/` | команды argparse и печать; приложение FastAPI, маршруты и схемы ответов | правил контента |
| проверки | `wordforms/` | проверка словоформ: какие слова проверять и что о них говорит анализатор | правил формата файлов |
| контент | `content/` | предметная модель, чтение файлов и все правила их формата и связей | HTTP, печати, анализатора |
| настройки | `settings` | откуда читать контент | всего остального |

`api` и `wordforms` друг о друге не знают. `cli` — единственный модуль, который собирает их вместе.

Предметная модель — `content.model`: замороженные dataclass без ввода-вывода (`Topic`, `Example`, `Contrast`, `Catalog` и т.д.). `content.graph` — производное от неё: граф тем вычисляется из `Catalog` и в файлах не хранится. Pydantic-модели живут на границах: `content.files` описывает форму файлов, `api.schemas` — форму ответов API. Модель из файлов строит `content.loader`, ответы из модели — `api.routes` через `model_validate`.

zeyrek — зависимость разработки. Его импортирует только `wordforms.analyzer`, и только при первом обращении: серверу анализатор не нужен.

## Карта кода

У каждого модуля есть строка здесь и докстринг, который называет его роль не длиннее чем в трёх строках; подробности живут здесь или в спецификации. `backend/tests/test_architecture.py` проверяет и то и другое: модуль без строки, строку без модуля, модуль без докстринга или со слишком длинным. Докстринг пакета называет роль слоя, а не его модули; `__init__.py` получает строку, только если в нём есть функции или классы.

| Пакет | Модуль | За что отвечает |
|---|---|---|
| | `settings` | `Settings`: каталог контента из `CONTENT_DIR`, по умолчанию `content/` в корне; `REPO_ROOT`. |
| | `cli` | Команды `turkish-grammar`: `check-content`, `check-words`, `summarize-content`, `export-openapi`. Анализатор импортирует внутри `check-words`. |
| `api` | `app` | `create_app`: контент загружается в `lifespan`, а не при сборке, поэтому описание API доступно и без контента; там же из каталога строится граф тем. С невалидным контентом сервер не стартует. Имя операции в OpenAPI — имя функции. |
| | `routes` | Пять `GET` под `/api`: `topics`, `sections`, `topics/{id}`, `graph`, `notation`. Только читают `Catalog` и `TopicGraph` из `app.state` и переводят их в схемы ответов; неизвестная тема — 404. |
| | `schemas` | Pydantic-схемы ответов; из них строится OpenAPI, а из него — типы интерфейса. |
| `content` | `model` | Предметная модель: `Level`, `Topic` (обзор — тема с `members`), `Example`, `GlossedWord`, `Section`, `Contrast`, `Abbreviation`, `KnownWord`, `Catalog`; `ARTICLE_TEMPLATE` — блоки статьи в их порядке. |
| | `files` | Форма файлов контента — метаданных темы, примера, раздела, различения, обозначения, известного слова (Pydantic, лишние поля запрещены) — и перевод ошибок Pydantic в сообщения автору. |
| | `loader` | `load_catalog`: два прохода — каждый файл сам по себе, затем связи (ссылки, обзоры, различения, учебный маршрут, уровни, разделы, обозначения); собирает все ошибки сразу. Обзор и различение сверяет со ссылками `topic:<id>` в статьях. `load_known_words`. Имена файлов контента — константы здесь. |
| | `graph` | `build_graph`: граф тем из каталога — связи трёх видов (пререквизит, тема обзора, связанная тема) в порядке учебного маршрута и обратные индексы темы: её обзоры, различения и связанные темы без повторов. Здесь живёт правило «связанная тема уступает более определённой связи». |
| | `article` | Разбор `topic.md`: метаданные, блоки по шаблону, ссылки на темы. Через markdown-it-py, а не по строкам: заголовок внутри блока кода не должен стать заголовком блока статьи, а ссылки нужны вместе с адресами. В HTML текст не превращает — это делает интерфейс. |
| | `gloss` | Разбор по морфемам: строки `morphemes` и `gloss` → слова и морфемы; сверка с текстом примера. |
| | `markup` | Выделение звёздочками в тексте примера → отрезки текста. |
| | `turkish` | Турецкий нижний регистр (I → ı, İ → i) и нормализация текста для сверки. |
| | `errors` | `ContentIssue`, `InvalidContentError` со всеми ошибками, `format_issues` — отчёт для человека. |
| | `summary` | Сводка наполнения: темы и заглушки по уровням, примеры у написанных тем. |
| `wordforms` | `extraction` | Какие слова контента турецкие: в поле `tr` примера — каждое слово; в русских текстах (название, суть, статья, название различения, вводный текст к обозначениям) — слово, набранное латиницей. Ищет и смешение алфавитов в одном слове. |
| | `analyzer` | Единственный модуль, который знает о zeyrek: `is_recognized`. zeyrek импортируется при первом обращении, а не вместе с модулем: серверу он не нужен. |
| | `check` | `check_word_forms`: слова, которых не признаёт анализатор и которых нет в списке известных слов; проверка самого списка. |

## Потоки

**Старт сервера** (`mise run dev:backend`). uvicorn поднимает `api.app:app` → `lifespan` вызывает `load_catalog`, затем `build_graph` → `Catalog` и `TopicGraph` кладутся в `app.state`. Ошибка контента — отчёт в лог, сервер не стартует. В разработке uvicorn перезапускается при правке кода и файлов `content/`.

**Проверка контента** (`mise run content:check`). `cli check-content` → `load_catalog` → все ошибки с файлом и причиной, код выхода 1; без ошибок — число тем и заглушек.

**Проверка словоформ** (`mise run content:words`). Сначала та же загрузка каталога. Затем `wordforms.extraction.find_words` собирает слова, `analyzer.is_recognized` проверяет каждое, `check` вычитает известные слова из `content/known-words.yaml`. На старт сервера не влияет. Переход с zeyrek на Zemberek запланирован; код, который знает об анализаторе, — только `analyzer`.

**Типы интерфейса** (`mise run gen:api`). `cli export-openapi` пишет `frontend/openapi.json` (в git не хранится), openapi-typescript генерирует `frontend/src/api/schema.d.ts` (хранится в git, руками не правится). `gen:api:check` входит в `mise run check` и падает, если сохранённый файл отстал от схем.

## Интерфейс

`frontend/` — Vite, React, TypeScript, Tailwind, TanStack Query, react-router. Карта тем добавляет две зависимости: `@xyflow/react` (React Flow — холст с перемещением, масштабом и узлами-компонентами) и `d3-hierarchy` (раскладка дерева). В разработке Vite проксирует `/api` на `127.0.0.1:8000`.

- `src/api/client.ts` — единственный модуль, который ходит в сеть (openapi-fetch по `schema.d.ts`); `ApiError`, `isNotFound`.
- `src/api/types.ts` — псевдонимы `components["schemas"]`; своих типов ответов в интерфейсе нет.
- `src/api/queries.ts` — `queryOptions`: ключи и загрузчики. Карте тем нужны два запроса: граф тем (`graphQuery`, `GET /api/graph`) — из него она берёт и сами темы в порядке учебного маршрута — и разделы (`sectionsQuery`). Список тем `GET /api/topics` интерфейс не запрашивает.
- `src/lib/` — чистые функции: адреса страниц (`site.ts`), шаблон страницы темы (`template.ts`, `TEMPLATE`: семь блоков в их порядке и заголовки). Четыре блока — текст статьи с сервера; «Примеры», «Не путать» и «Связанные темы» страница собирает сама из примеров и связей темы. Новый вид блока на сервере ломает компиляцию, пока ему не дадут место.
- `src/lib/map*.ts` — логика карты тем, чистые функции без холста:
  - `mapTree.ts` — `buildMapTree`: дерево видимых узлов по включённым уровням и развёрнутым разделам. Родитель темы — первый по учебному маршруту видимый обзор её раздела, в который она входит, иначе раздел; связи «тема обзора», не ставшие веткой, возвращаются отдельно.
  - `mapLayout.ts` — `splitSections` делит разделы между правой и левой сторонами по полному числу тем, один раз; `layoutMap` раскладывает каждую сторону `tree()` из `d3-hierarchy` с фиксированным шагом и отражает левую по горизонтали. Узел раздела выше узла темы — его название занимает до трёх строк, — поэтому соседние разделы стоят дальше друг от друга, чем темы, с тем же просветом.
  - `mapLinks.ts` — `crossLines`: перекрёстные линии между видимыми темами (связи с обзорами вне веток, включённые слои, все связи темы, которая выбрана или на узел которой навели; различение — линиями между каждой парой); `topicLinks`: связи темы по видам, в порядке маршрута, — из них окно темы берёт список «Нужна для» — и `linkedTopicIds`: темы, узлы которых рядом с выбранной не приглушаются.
  - `mapSettings.ts` — то, что карта хранит в `localStorage`, под двумя ключами. `topic-map-view` — настройки вида (уровни, слои, развёрнутые разделы): чтение с отбрасыванием неизвестного и испорченного, умолчания, переключение уровня, раскрытие темы. `topic-map-viewport` — положение карты (сдвиг и масштаб); испорченное или неполное значение отбрасывается целиком. Ключи разные, потому что от настроек зависит раскладка, а положение меняется при каждом сдвиге.
  - `mapFlow.ts` — раскладка и линии в виде узлов и линий React Flow: размеры, точки крепления, начертание, имена линий для программ чтения с экрана, приглушение узлов, не связанных с подсвеченной темой; `nodeFitsCanvas` — виден ли узел на холсте целиком. `mapStyle.ts` — тон уровня и начертание линии каждого вида, общие для холста и условных обозначений.
- `src/components/` — `Layout` (шапка: название справочника и ссылка «Карта тем» — других ссылок и списка тем в ней нет; со страницы темы обе ведут на карту к этой теме, `/?topic=<id>`, с остальных страниц — на `/`; у карты вид широкий: содержимое занимает всё место под шапкой без полей и прокрутки, у остальных страниц — колонка по центру), `TopicArticle` (содержимое темы по шаблону — одно для страницы темы и окна темы на карте), `topicHref.ts` (`TopicHrefContext` — куда ведёт ссылка на тему: по умолчанию на её страницу; его читают ссылки на темы в `TopicArticle` и ссылки `topic:<id>` в `ArticleMarkdown`), `ArticleMarkdown`, `ExampleCard`, `GlossView` (разбор по морфемам таблицей из двух строк), `AffixText` (запись аффикса без переноса), `TopicMarks` (`StubMark` — пометка «не написано» у ссылки на заглушку), `QueryView` (загрузка и ошибка; `Loading` показывает и маршрут карты, пока грузится её код). Карта тем: `MapNodes` (узлы корня, раздела и темы — кнопка внутри узла, фокус получает она, а не обёртка React Flow), `MapEdges` (`ArcEdge` — линия между темами одного столбца: дуга, выгнутая наружу, тем сильнее, чем дальше темы друг от друга; путь считает `arcPath` из `mapFlow.ts`), `mapNodeActions.ts` (контекст: выбор темы, сворачивание раздела и подсветка связей темы, пока на её узле указатель мыши или фокус клавиатуры), `MapTopicDialog` (окно темы поверх карты: `TopicArticle` под `TopicHrefContext` с адресами карты, поэтому ссылки на темы открывают их в том же окне; сверх содержимого страницы — список «Нужна для», который карта берёт из графа, потому что в ответе о теме его нет; длинный список свёрнут под подписью с числом тем; действия «Развернуть» — ссылка на страницу темы — и «Закрыть»), `MapToolbar` (переключатели слоёв и уровней, «Показать всё», «Развернуть все»; на узком экране — сворачиваемый блок), `MapLegend` (условные обозначения).
- `src/pages/` — `MapPage` (`/`, главная), `TopicPage` (`/topics/:id`), `NotationPage` (`/notation`; ссылка на неё — только в блоке «Примеры» темы с разбором), `NotFoundPage`. Маршруты собирает `src/AppRoutes.tsx`; старый адрес карты `/map` перенаправляется на `/` с той же строкой запроса. `TopicPage` добавляет к `TopicArticle` заголовок вкладки. В `TopicArticle` место темы на карте — пререквизиты, «Входит в обзор», «Темы обзора» — показывает один компонент `TopicLinks` в начале, а блок «Не путать» — `Contrasts`: название различения, остальные его темы и ссылка «Разбор», если различие разобрано не в этой теме. У заглушки вместо статьи сообщение, а блоки из связей остаются. Учебный маршрут в интерфейсе виден только здесь: переходами «Предыдущая тема» и «Следующая тема».
- `src/pages/MapPage.tsx` — карта тем: соединяет функции `src/lib/map*.ts` с React Flow, адресом и хранилищем. Выбранная тема живёт в адресе (`/?topic=<id>`), и это же значит «окно темы открыто»: закрытие окна убирает тему из адреса, а отдельного состояния «выбрана, но окно закрыто» нет. Переходы между темами в окне и закрытие кладут записи в историю, поэтому кнопка браузера «Назад» листает темы. Адрес главнее сохранённых настроек: тема из нового адреса раскрывает свой раздел и уровень, а если её узел не виден на холсте целиком, вид сдвигается к нему. Положение карты читается из хранилища один раз, при открытии страницы, и записывается после каждого сдвига, масштаба и анимации (`onMoveEnd`); вписывается в экран карта только тогда, когда сохранённого положения нет, и по действиям «Показать всё» и «Развернуть все» — с отступами под блок переключателей. Поэтому возврат со страницы темы обходится без своей истории: ссылка в шапке даёт тему, хранилище — место на карте. Связи темы карта показывает и без выбора: подсвечена выбранная тема, а пока выбора нет — та, на узел которой навели; выделение получает только выбранный узел. Окно темы — модальный `<dialog>`: неактивный фон, фокус внутри окна, закрытие по Escape и возврат фокуса на узел темы даёт браузер, а не свой код. Маршрут подключён через `React.lazy`, поэтому React Flow, `d3-hierarchy` и стили холста лежат в отдельном файле сборки: страница темы, открытая по прямой ссылке, их не грузит.

## Тесты

Сервер — pytest в `backend/tests/`, по подпакетам: `content/`, `api/`, `wordforms/`. Контент для тестов собирает `ContentBuilder` из `tests/support.py` во временной папке; настоящий `content/` тесты не читают, кроме `test_author_guide.py`, который прогоняет через проверку образцы из `content/README.md`. Тесты словоформ подставляют `FakeAnalyzer` вместо zeyrek. `test_architecture.py` не повторяет ни одного модуля: он разбирает модули через `ast` и сверяет их докстринги и карту кода в этом файле.

Интерфейс — Vitest и Testing Library рядом с кодом (`*.test.tsx`), сеть подменяет msw (`src/test/server.ts`), данные — `src/test/fixtures.ts` (там же тестовый граф тем). Холсту React Flow в jsdom нужны заглушки окружения — наблюдатель размеров, `DOMMatrixReadOnly`, размеры элементов, — а окну темы — `showModal` и `close` у `<dialog>`; они в `src/test/setup.ts`, а `src/test/setup.test.tsx` проверяет, что с ними холст рисуется, а окно открывается и закрывается. Логику карты проверяют модульные тесты `src/lib/map*.test.ts`; тесты `MapPage` проверяют только связку: узлы, выбор, окно темы, адрес, хранилище. Жесты, вид на узком экране и то, что в модальном окне делает браузер, — неактивный фон, фокус, Escape — проверяются в браузере.
