# Руководство автора контента

Весь контент справочника лежит в этом каталоге. Сервер проверяет его целиком и не стартует, пока есть хотя бы одна ошибка. Проверка без сервера:

```sh
mise run content:check
```

Команда печатает все ошибки сразу: файл и причину.

Вторая проверка — словоформ: она ищет турецкие слова, которых не существует. Сервер от неё не зависит, но в `mise run check` она входит. Подробности — в разделе [«Проверка словоформ»](#проверка-словоформ).

```sh
mise run content:words
```

Контент готов, когда проходят обе команды.

## Что где лежит

```
content/
  sections.yaml         разделы и их порядок
  path.yaml             учебный маршрут: порядок всех тем
  abbreviations.yaml    обозначения для разборов по морфемам
  notation.md           вводный текст страницы «Обозначения»
  known-words.yaml      список известных слов для проверки словоформ
  topics/<id>/
    topic.md            метаданные темы и текст статьи
    examples.yaml       примеры темы
```

Термины («тема», «заглушка», «суть», «блок статьи»…) определены в [GLOSSARY.md](../GLOSSARY.md).

## Карта тем

**Одна тема — одно явление**: один аффикс или одна конструкция. Группу явлений показывает отдельная тема-обзор (`cases-overview`), которая ссылается на темы об отдельных явлениях и не заменяет их. Тема, которая объясняет два независимых аффикса, делится на две.

**Идентификатор** темы — имя её каталога. Он входит в адрес страницы, поэтому после появления остаётся прежним. Идентификатор английский, в kebab-case: строчные латинские буквы, цифры и дефисы. Аффикс записывается латиницей без диакритики: `vowel-harmony`, `plural-lar`, `locative-da`, `past-di`.

**Название** — русское название явления и аффикс в записи с заглавными буквами для чередующихся звуков: «Местный падеж -DA», «Множественное число -lAr». Как читать такую запись, объясняет `notation.md`.

**Язык**: название, суть и статья — на русском. Каждый пример — на турецком с русским переводом.

**Пререквизиты** — все темы, без которых эту тему понять нельзя, и только они. Тематически близкая, но необязательная тема идёт в `related`. Пререквизитом может быть заглушка.

**Уровень** берётся из источников карты, записанных в `docs/topic-map-sources.md`.

## Файл темы

`topic.md` начинается с метаданных между строками `---`. Обязательны `title`, `section`, `level`, `prerequisites` и `summary`; `related` можно опустить. Других полей нет: опечатка в имени поля — ошибка.

| Поле            | Что в нём                                                                 |
| --------------- | ------------------------------------------------------------------------- |
| `title`         | название темы                                                             |
| `section`       | идентификатор раздела из `sections.yaml`                                  |
| `level`         | `A1`, `A2`, `B1` или `B2`                                                 |
| `prerequisites` | список идентификаторов тем; пустой список — `[]`                          |
| `related`       | список идентификаторов связанных тем                                      |
| `summary`       | суть: одна фраза о том, что это за явление и что оно выражает             |

Суть показывается в списках тем, на странице заглушки и в начале статьи, поэтому в тексте статьи она не повторяется.

`content/topics/locative-da/topic.md`:

```markdown
---
title: Местный падеж -DA
section: nouns
level: A1
prerequisites: [vowel-harmony, consonant-assimilation]
related: [ablative-dan]
summary: Показывает, где что-то находится или когда происходит; отвечает на вопросы «где?» и «когда?».
---

## Формула

Основа + **-DA**: -da / -de / -ta / -te. Гласную выбирает [гармония гласных](topic:vowel-harmony).

## Формы

| Последний звук основы           | После a, ı, o, u | После e, i, ö, ü |
| ------------------------------- | ---------------- | ---------------- |
| гласный или звонкий согласный   | okul**da**       | ev**de**         |
| глухой (p, ç, t, k, f, h, s, ş) | kitap**ta**      | sepet**te**      |

## Подводные камни

### Аффикс и частица

Аффикс -DA пишется слитно. Отдельное слово *da / de* — это частица «тоже»: *Ben **de** evdeyim* — «Я тоже дома».

## Сравнение с русским

В русском место выражает предлог с падежом («в доме», «на столе»). В турецком предлога нет: и «в», и «на» передаёт один аффикс.
```

### Шаблон статьи

Статья состоит из блоков. Блок начинается заголовком второго уровня, и допустимы только эти четыре заголовка, именно в таком порядке:

| Заголовок                | Что писать                                                                    |
| ------------------------ | ----------------------------------------------------------------------------- |
| `## Формула`             | как образуется форма: основа, аффикс и его варианты; что форма выражает       |
| `## Формы`               | таблица вариантов или парадигма                                               |
| `## Подводные камни`     | исключения, частые ошибки, с чем это явление путают                           |
| `## Сравнение с русским` | чем явление похоже на русскую грамматику и чем отличается                     |

Значения аффикса перечисляют в блоке «Формула» под подзаголовком `### Что выражает`: отдельного блока для них в шаблоне нет.

Любой блок можно пропустить. Весь текст стоит внутри блоков: до первого заголовка `##` в статье пусто. Блоки «Примеры» и «Связанные темы» страница собирает сама из `examples.yaml` и поля `related` и ставит «Примеры» после «Форм», а «Связанные темы» — в конец.

Внутри блока работает Markdown: таблицы, списки, выделение, подзаголовки начиная с `###`. HTML-разметка показывается как текст.

Ссылка на другую тему пишется с адресом `topic:<id>`: `[гармония гласных](topic:vowel-harmony)`. Внешняя ссылка — с полным адресом `https://…`.

### Заглушка

Тема без единого блока — заглушка: у неё есть место на карте тем, но статья ещё не написана. Примеры ей не нужны.

`content/topics/ablative-dan/topic.md`:

```markdown
---
title: Исходный падеж -DAn
section: nouns
level: A1
prerequisites: [vowel-harmony, consonant-assimilation]
related: [locative-da]
summary: Показывает, откуда начинается движение или из чего что-то сделано; отвечает на вопросы «откуда?» и «от кого?».
---
```

## Примеры

У темы со статьёй есть хотя бы один пример. Примеры лежат списком в `examples.yaml`.

| Поле        | Что в нём                                                                          |
| ----------- | ---------------------------------------------------------------------------------- |
| `tr`        | турецкий текст — обязательно                                                       |
| `ru`        | русский перевод — обязательно                                                      |
| `morphemes` | разбор по морфемам: слова примера, разбитые на морфемы                             |
| `gloss`     | разбор по морфемам: значения этих морфем                                           |
| `note`      | примечание к примеру, обычный текст                                                |
| `source`    | `authored` (по умолчанию) или `generated` — для примеров, созданных автоматически  |

Изучаемую часть слова в `tr` и `ru` выделяют парой звёздочек: `Ev*de*yim.`

Значение, которое начинается со звёздочки или содержит двоеточие с пробелом, берут в кавычки, иначе YAML прочитает его по-своему: `tr: "*Ev*de"`.

`content/topics/locative-da/examples.yaml`:

```yaml
- tr: Ev*de*yim.
  ru: Я *дома*.
  morphemes: ev-de-yim
  gloss: дом-МЕСТ-1ЕД
- tr: Kitap masa*da*.
  ru: Книга *на столе*.
  note: Последняя гласная слова masa — a, поэтому вариант -da.
- tr: İstanbul'*da* yaşıyorum.
  ru: Я живу *в Стамбуле*.
  morphemes: istanbul-da yaşı-yor-um
  gloss: Стамбул-МЕСТ жить-НАСТ-1ЕД
```

### Разбор по морфемам

Разбор — две параллельные строки, которые задаются только вместе. В обеих слова разделены пробелами, а морфемы — дефисами; число слов и число морфем в каждом слове совпадает.

- **Разбирается записанная форма**, а не словарная: `gid-iyor`, а не `git-iyor`. Строка `morphemes` без дефисов совпадает с `tr`; регистр, пунктуация, апостроф и звёздочки при сверке не учитываются. Регистр сравнивается по-турецки: `I` — это `ı`, `İ` — это `i`.
- **Разбирается весь текст примера**, каждое слово. Слово без аффиксов — одна морфема.
- **Обозначение** — значение без строчных букв: `МН`, `1ЕД`. Каждое обозначение есть в `abbreviations.yaml`; новое сначала добавляют туда.
- **Лексическое значение** пишется строчными: `дом`, `Стамбул`. Перевод из нескольких слов соединяют точкой, потому что дефис и пробел заняты: `потому.что`, `кто.то`.
- **Составное значение** одной морфемы тоже соединяют точкой: `1ЕД.ПРИТ`. Его части проверяются по отдельности.

## Как писать тему

Написанная тема — это статья по шаблону и примеры к ней. Образцом служат три пилотные темы: `vowel-harmony`, `plural-lar` и `locative-da`.

Темы пишутся в порядке учебного маршрута: так каждая может ссылаться на уже написанные. На уровне A1 заглушек нет — каждая его тема написана.

### Что писать в блоках

Шаблон статьи один, а темы разные. Что стоит в блоках «Формула» и «Формы», зависит от типа темы:

| Тип темы       | Темы такого типа                                            | «Формула»                                                              | «Формы»                                        |
| -------------- | ----------------------------------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------- |
| Аффикс         | падежи, времена, `suffix-li-siz`, `ordinal-inci`            | основа + аффикс и от чего зависят его варианты; `### Что выражает`     | таблица вариантов или парадигма по лицам       |
| Правило звуков | `consonant-softening`, `vowel-narrowing`, `vowel-drop`      | что на что меняется и в каком окружении                                | таблица чередований с парами слов              |
| Конструкция    | изафет, `var-yok`, `want-mak-istemek`, послелоги, сравнение | схема по позициям: какое слово в какой форме стоит; `### Что выражает` | варианты схемы: по лицам, с отрицанием, вопрос |
| Группа слов    | вопросительные слова, наречия, союзы, числительные          | где слово стоит в предложении и чего требует от соседей                | таблица слов с переводом                       |
| Обзор          | `cases-overview`                                            | что объединяет группу и как выбрать между её членами                   | сводная таблица со ссылками на темы            |
| Письмо         | `alphabet`, `apostrophe`                                    | само правило                                                           | таблица букв или случаев                       |

Блоки «Подводные камни» и «Сравнение с русским» пишутся одинаково для всех типов. Блок, в котором нечего сказать, пропускается.

### Глубина изложения

- **Объём** — один–три экрана, как у пилотных тем.
- **Уровень.** Тема уровня A1 даёт основное значение и формы, которые начинающий встречает сам. О более сложном достаточно сказать коротко; если у него есть своя тема, на неё дают ссылку.
- **«Подводные камни»** — самые частые ошибки русскоязычного ученика, обычно от двух до четырёх, каждая под своим подзаголовком `###`.
- **Явление объясняется в своей теме.** Если у явления есть собственная тема, правило излагает только она. Любая другая тема даёт о нём одну фразу, при необходимости с примером, и ссылку: «После аффикса принадлежности 3-го лица появляется [вставное n](topic:pronominal-n): *evi → evinde*».
- **У явления одно название** во всех темах. Термины берутся из названий тем на карте и из уже написанных тем: «аффикс», «основа», «аффикс принадлежности», «аффиксы сказуемости».
- **Сомнительное сверяется с источником.** Утверждение о языке, в котором нет уверенности, сверяют с открытым источником: словарём TDK (sozluk.gov.tr), справочными страницами университетских центров TÖMER, Vikisözlük. Утверждение, которое подтвердить не удалось, в статью не попадает.

### Неверные формы

Неверную форму, которую статья приводит как ошибку, зачёркивают, а рядом ставят верную:

```markdown
После глухого согласного пишут не ~~sokakda~~, а *sokakta*.
```

Читатель видит, что форма неверная, даже если пропустил слово «не», а проверка словоформ зачёркнутый текст не читает.

В примерах неверных форм нет: каждый `tr` — правильный турецкий текст.

### Сколько примеров и какие

- **Объём.** У темы не меньше шести примеров, обычно до десяти. Если в примерах есть слова с аффиксами, не меньше трёх примеров имеют разбор по морфемам. Теме, в примерах которой аффиксов нет, разбор не нужен: такова тема об алфавите.
- **Порядок** — от отдельной словоформы к предложению.
- **Полнота.** Варианты аффикса из таблицы форм и значения из «Что выражает» показаны примерами. У большой парадигмы хватает примера на каждое лицо: показывать каждую клетку таблицы не нужно.
- **Выделение.** Изучаемая часть выделена звёздочками в `tr`. В `ru` выделяют соответствующую часть перевода, если её можно указать.
- **Лексика** бытовая, начального уровня: дом, семья, еда, город, учёба, время. Слово не должно быть труднее грамматики, которую оно показывает.
- **Разбор** ставят там, где он помогает прочитать пример: у слова с несколькими аффиксами, у чередования в основе, у формы, которую маршрут объясняет позже. Запрета на такие формы нет: пример может забегать вперёд, а читатель — заглянуть в следующую тему.
- **Примечание** (`note`) пишут, когда выбор формы неочевиден: почему взят этот вариант аффикса или чем буквальный смысл отличается от перевода.

Число примеров кодом не проверяется. Его показывает сводка наполнения — для каждой написанной темы число примеров и число примеров с разбором:

```sh
mise run content:stats
```

### Проверка словоформ

`mise run content:words` отдаёт турецкие слова контента морфологическому анализатору и печатает те, которых он не признаёт, вместе с файлом. Так находятся ошибки в гармонии гласных, чередованиях и написании.

**Что проверяется:**

- каждое слово в `tr` примеров;
- каждое слово, набранное латиницей, — в названии, сути, статье и `notation.md`;
- слово, разбитое на морфемы дефисами или на части выделением, — в слитном виде: `okul-lar-ımız-da` и `kitap**lar**` проверяются как *okullarımızda* и *kitaplar*.

**Что не проверяется:**

- формула аффикса — запись, которая начинается с дефиса либо содержит скобку, косую черту или заглавную букву после строчной: `-lAr`, `-da`, `-(y)I`, `mI`;
- отдельная буква: `p, ç, t, k`;
- зачёркнутый текст и адрес ссылки;
- запись с цифрой: `2020'de`, `5'te`.

Слово, в котором смешаны латинские и кириллические буквы, — всегда ошибка: команда называет и слово, и чужие буквы в нём.

**Если команда назвала слово**, сначала исправляют ошибку. Верное слово, которого анализатор не знает, вносят в список известных слов вместе с причиной.

`content/known-words.yaml`:

```yaml
- word: durmaksızın
  reason: Деепричастие на -mAksIzIn от durmak; аффикс книжный, и анализатор его не знает.
```

Запись без причины — ошибка. Лишняя запись — тоже ошибка: слово, которое анализатор признаёт или которого в контенте уже нет, из списка убирают.

Анализатор замечает не всё: форму *kitapı* вместо *kitabı* он признаёт. Озвончение конечной согласной, выпадение гласной и аффиксы после чисел проверяют при вычитке.

## Соглашения разбора

Одни и те же формы встречаются в десятках тем, поэтому спорные случаи решены один раз. В каждом пункте сначала записана строка `morphemes`, после тире — строка `gloss`.

1. **Суженная гласная остаётся в своей морфеме**, а аффикс настоящего времени после гласной — `-yor`: `bekli-yor` — `ждать-НАСТ`, `gel-mi-yor-um` — `приходить-ОТР-НАСТ-1ЕД`. После согласного аффикс — `-iyor`: `gel-iyor` — `приходить-НАСТ`. Так в разборе видно отрицание `-mi-`.
2. **Соединительный согласный пишется вместе с аффиксом**: `araba-yı` — `машина-ВИН`, `araba-nın` — `машина-РОД`, `araba-sı` — `машина-3ЕД.ПРИТ`.
3. **Вставное n пишется вместе с падежным аффиксом**: `ev-i-nde` — `дом-3ЕД.ПРИТ-МЕСТ`. Запись `ev-in-de` читалась бы как аффикс принадлежности 2-го лица.
4. **Основа записана так, как стоит в слове**: `kitab-ı` — `книга-ВИН`, `gid-iyor` — `идти-НАСТ`, `burn-u` — `нос-3ЕД.ПРИТ`, `ban-a` — `я-ДАТ`, `bun-lar` — `этот-МН`.
5. **Нулевых морфем нет.** У третьего лица нет личного аффикса, и разбор его не показывает: `gel-di` — `приходить-ПРОШ`.
6. **Вопросительная частица — отдельное слово**: `gel-iyor mu` — `приходить-НАСТ ВОПР`, `öğrenci mi-sin` — `студент ВОПР-2ЕД`.
7. **Личные аффиксы сказуемости и глагола подписаны одними и теми же кодами лиц**: `öğrenci-yim` — `студент-1ЕД`, `gel-di-m` — `приходить-ПРОШ-1ЕД`.
8. **Аффикс, который нельзя разделить без потери смысла, получает составное значение**: `gel-elim` — `приходить-ЖЕЛ.1МН`, `gel-in` — `приходить-ПОВ.2МН`, `ev-imiz` — `дом-1МН.ПРИТ`.
9. **Составная форма делится по аффиксам**: `gel-iyor-du-m` — `приходить-НАСТ-ПРОШ-1ЕД`, `çalış-mak-ta-yım` — `работать-ИНФ-МЕСТ-1ЕД`.
10. **Служебные слова переводятся**: `değil` — `не`, `var` — `есть`, `yok` — `нет`, `için` — `для`, `daha` — `более`.
11. **Словообразовательный аффикс выделяется только в теме, которая его изучает.** В остальных темах словарное слово — одна морфема: `öğrenci-ler` — `студент-МН`, `bugün` — `сегодня`, `türkçe` — `турецкий.язык`. Местоимение *onlar* — тоже одна морфема: `onlar` — `они`. Падежный аффикс при местоимении отделяется, как в пункте 4.
12. **Новое обозначение добавляется в `abbreviations.yaml` в той же правке, что и первая тема, которой оно нужно.** Теме о порядковых числительных нужно обозначение ПОРЯД: `üç-üncü` — `три-ПОРЯД`.

## Справочные файлы

`content/sections.yaml` — разделы в том порядке, в котором их видит читатель. В каждом разделе есть хотя бы одна тема.

```yaml
- id: phonetics
  title: Фонетика и письмо
- id: nouns
  title: Существительное
```

`content/path.yaml` — учебный маршрут: идентификаторы всех тем, каждая ровно один раз. Пререквизит стоит раньше темы, которая его требует. Уровни не убывают: сначала все темы A1, затем A2, B1 и B2. Новая тема сразу получает строку в маршруте.

```yaml
- vowel-harmony
- consonant-assimilation
- locative-da
- ablative-dan
```

`content/abbreviations.yaml` — обозначения в том порядке, в котором их показывает страница «Обозначения». Код уникален и записан заглавными буквами без пробелов, точек и дефисов.

```yaml
- code: МЕСТ
  meaning: местный падеж
- code: 1ЕД
  meaning: первое лицо единственного числа
- code: НАСТ
  meaning: настоящее время
```

`content/notation.md` — свободный текст в Markdown о том, как читать формулы аффиксов и разборы по морфемам.
