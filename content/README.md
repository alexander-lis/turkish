# Руководство автора контента

Весь контент справочника лежит в этом каталоге. Сервер проверяет его целиком и не стартует, пока есть хотя бы одна ошибка. Проверка без сервера:

```sh
mise run content:check
```

Команда печатает все ошибки сразу: файл и причину. Контент готов, когда она проходит.

## Что где лежит

```
content/
  sections.yaml         разделы и их порядок
  path.yaml             учебный маршрут: порядок всех тем
  abbreviations.yaml    обозначения для разборов по морфемам
  notation.md           вводный текст страницы «Обозначения»
  topics/<id>/
    topic.md            метаданные темы и текст статьи
    examples.yaml       примеры темы
```

Термины («тема», «заглушка», «суть», «блок статьи»…) определены в [GLOSSARY.md](../GLOSSARY.md).

## Карта тем

**Одна тема — одно явление**: один аффикс или одна конструкция. Группу явлений показывает отдельная тема-обзор (`cases-overview`), которая ссылается на темы об отдельных явлениях и не заменяет их. Тема, которая объясняет два независимых аффикса, делится на две.

**Идентификатор** темы — имя её каталога. Он входит в адрес страницы, поэтому после появления остаётся прежним. Идентификатор английский, в kebab-case: строчные латинские буквы, цифры и дефисы. Аффикс записывается латиницей без диакритики: `vowel-harmony`, `plural-lar`, `locative-da`, `past-di`.

**Название** — русское название явления и аффикс в записи с заглавными буквами для чередующихся звуков: «Местный падеж -DA», «Множественное число -lAr». Как читать такую запись, объясняет `notation.md`.

**Язык**: название, суть и статья — на русском. Каждый пример — на турецком с русским переводом.

**Пререквизиты** — все темы, без которых эту тему понять нельзя, и только они. Тематически близкая, но необязательная тема идёт в `related`. Пререквизитом может быть заглушка.

**Уровень** берётся из источников карты, записанных в `docs/topic-map-sources.md`.

## Файл темы

`topic.md` начинается с метаданных между строками `---`. Обязательны `title`, `section`, `level`, `prerequisites` и `summary`; `related` можно опустить. Других полей нет: опечатка в имени поля — ошибка.

| Поле            | Что в нём                                                                 |
| --------------- | ------------------------------------------------------------------------- |
| `title`         | название темы                                                             |
| `section`       | идентификатор раздела из `sections.yaml`                                  |
| `level`         | `A1`, `A2`, `B1` или `B2`                                                 |
| `prerequisites` | список идентификаторов тем; пустой список — `[]`                          |
| `related`       | список идентификаторов связанных тем                                      |
| `summary`       | суть: одна фраза о том, что это за явление и что оно выражает             |

Суть показывается в списках тем, на странице заглушки и в начале статьи, поэтому в тексте статьи она не повторяется.

`content/topics/locative-da/topic.md`:

```markdown
---
title: Местный падеж -DA
section: nouns
level: A1
prerequisites: [vowel-harmony, consonant-assimilation]
related: [ablative-dan]
summary: Показывает, где что-то находится или когда происходит; отвечает на вопросы «где?» и «когда?».
---

## Формула

Основа + **-DA**: -da / -de / -ta / -te. Гласную выбирает [гармония гласных](topic:vowel-harmony).

## Формы

| Последний звук основы           | После a, ı, o, u | После e, i, ö, ü |
| ------------------------------- | ---------------- | ---------------- |
| гласный или звонкий согласный   | okul**da**       | ev**de**         |
| глухой (p, ç, t, k, f, h, s, ş) | kitap**ta**      | sepet**te**      |

## Подводные камни

### Аффикс и частица

Аффикс -DA пишется слитно. Отдельное слово *da / de* — это частица «тоже»: *Ben **de** evdeyim* — «Я тоже дома».

## Сравнение с русским

В русском место выражает предлог с падежом («в доме», «на столе»). В турецком предлога нет: и «в», и «на» передаёт один аффикс.
```

### Шаблон статьи

Статья состоит из блоков. Блок начинается заголовком второго уровня, и допустимы только эти четыре заголовка, именно в таком порядке:

| Заголовок                | Что писать                                                                    |
| ------------------------ | ----------------------------------------------------------------------------- |
| `## Формула`             | как образуется форма: основа, аффикс и его варианты; что форма выражает       |
| `## Формы`               | таблица вариантов или парадигма                                               |
| `## Подводные камни`     | исключения, частые ошибки, с чем это явление путают                           |
| `## Сравнение с русским` | чем явление похоже на русскую грамматику и чем отличается                     |

Значения аффикса перечисляют в блоке «Формула» под подзаголовком `### Что выражает`: отдельного блока для них в шаблоне нет.

Любой блок можно пропустить. Весь текст стоит внутри блоков: до первого заголовка `##` в статье пусто. Блоки «Примеры» и «Связанные темы» страница собирает сама из `examples.yaml` и поля `related` и ставит «Примеры» после «Форм», а «Связанные темы» — в конец.

Внутри блока работает Markdown: таблицы, списки, выделение, подзаголовки начиная с `###`. HTML-разметка показывается как текст.

Ссылка на другую тему пишется с адресом `topic:<id>`: `[гармония гласных](topic:vowel-harmony)`. Внешняя ссылка — с полным адресом `https://…`.

### Заглушка

Тема без единого блока — заглушка: у неё есть место на карте тем, но статья ещё не написана. Примеры ей не нужны.

`content/topics/ablative-dan/topic.md`:

```markdown
---
title: Исходный падеж -DAn
section: nouns
level: A1
prerequisites: [vowel-harmony, consonant-assimilation]
related: [locative-da]
summary: Показывает, откуда начинается движение или из чего что-то сделано; отвечает на вопросы «откуда?» и «от кого?».
---
```

## Примеры

У темы со статьёй есть хотя бы один пример. Примеры лежат списком в `examples.yaml`.

| Поле        | Что в нём                                                                          |
| ----------- | ---------------------------------------------------------------------------------- |
| `tr`        | турецкий текст — обязательно                                                       |
| `ru`        | русский перевод — обязательно                                                      |
| `morphemes` | разбор по морфемам: слова примера, разбитые на морфемы                             |
| `gloss`     | разбор по морфемам: значения этих морфем                                           |
| `note`      | примечание к примеру, обычный текст                                                |
| `source`    | `authored` (по умолчанию) или `generated` — для примеров, созданных автоматически  |

Изучаемую часть слова в `tr` и `ru` выделяют парой звёздочек: `Ev*de*yim.`

Значение, которое начинается со звёздочки или содержит двоеточие с пробелом, берут в кавычки, иначе YAML прочитает его по-своему: `tr: "*Ev*de"`.

`content/topics/locative-da/examples.yaml`:

```yaml
- tr: Ev*de*yim.
  ru: Я *дома*.
  morphemes: ev-de-yim
  gloss: дом-МЕСТ-1ЕД
- tr: Kitap masa*da*.
  ru: Книга *на столе*.
  note: Последняя гласная слова masa — a, поэтому вариант -da.
- tr: İstanbul'*da* yaşıyorum.
  ru: Я живу *в Стамбуле*.
```

### Разбор по морфемам

Разбор — две параллельные строки, которые задаются только вместе. В обеих слова разделены пробелами, а морфемы — дефисами; число слов и число морфем в каждом слове совпадает.

- **Разбирается записанная форма**, а не словарная: `gid-iyor`, а не `git-iyor`. Строка `morphemes` без дефисов совпадает с `tr`; регистр, пунктуация, апостроф и звёздочки при сверке не учитываются. Регистр сравнивается по-турецки: `I` — это `ı`, `İ` — это `i`.
- **Разбирается весь текст примера**, каждое слово. Слово без аффиксов — одна морфема.
- **Обозначение** — значение без строчных букв: `МН`, `1ЕД`. Каждое обозначение есть в `abbreviations.yaml`; новое сначала добавляют туда.
- **Лексическое значение** пишется строчными: `дом`, `Стамбул`. Перевод из нескольких слов соединяют точкой, потому что дефис и пробел заняты: `потому.что`, `кто.то`.
- **Составное значение** одной морфемы тоже соединяют точкой: `1ЕД.ПРИТ`. Его части проверяются по отдельности.

## Справочные файлы

`content/sections.yaml` — разделы в том порядке, в котором их видит читатель. В каждом разделе есть хотя бы одна тема.

```yaml
- id: phonetics
  title: Фонетика и письмо
- id: nouns
  title: Существительное
```

`content/path.yaml` — учебный маршрут: идентификаторы всех тем, каждая ровно один раз. Пререквизит стоит раньше темы, которая его требует. Уровни не убывают: сначала все темы A1, затем A2, B1 и B2. Новая тема сразу получает строку в маршруте.

```yaml
- vowel-harmony
- consonant-assimilation
- locative-da
- ablative-dan
```

`content/abbreviations.yaml` — обозначения в том порядке, в котором их показывает страница «Обозначения». Код уникален и записан заглавными буквами без пробелов, точек и дефисов.

```yaml
- code: МЕСТ
  meaning: местный падеж
- code: 1ЕД
  meaning: первое лицо единственного числа
```

`content/notation.md` — свободный текст в Markdown о том, как читать формулы аффиксов и разборы по морфемам.
