# Design

## Context

Мотивация и состав изменения — в proposal.md. Репозиторий пуст: есть только `README.md` из одной строки, `GLOSSARY.md` с терминами предметной области и каталог `openspec/`. Существующего кода, который надо учитывать, нет.

Ограничения, которые задают подход:

- Инструменты — только те, что сейчас считаются стандартом де-факто; mise настраивается с первого дня.
- Бэкенд на Python и интерфейс на React выбраны заранее: дальше появятся генерация примеров и закрепление с ИИ, и им нужен сервер, который владеет контентом.
- Контент пишется в файлах репозитория и в основном силами ИИ, а вычитывает его один человек. Поэтому проверка контента должна ловить как можно больше ошибок автоматически.
- Проверено на машине разработчика: установлены mise 2026.10.25 и uv 0.13.5; pnpm не установлен, его поставит mise. У репозитория есть remote на GitHub.

## Goals / Non-Goals

**Goals:**

- У модели контента один владелец — бэкенд. Интерфейс не читает файлы контента и не дублирует правила их проверки.
- Шаблон статьи и формат примера описаны в одном месте, так что их можно менять без переписывания тем.
- Формат примера и API уже сейчас вмещают сгенерированные примеры, хотя генерации ещё нет.
- Вся локальная работа идёт через задачи mise: одна команда поднимает справочник, одна проверяет всё.

**Non-Goals:**

- Серверный рендеринг, база данных, авторизация, кэширующие слои.
- Сборка для продакшена, Docker, деплой и CI. Remote на GitHub есть, но хостинг отложен, а CI логично добавлять вместе с ним.
- Тёмная тема и перевод интерфейса на другие языки.
- Сквозные тесты в браузере (Playwright): интерфейс покрывается компонентными тестами и ручной проверкой.
- Редиректы при переименовании тем.

## Decisions

### 1. Бэкенд владеет контентом, интерфейс читает его через API

FastAPI при старте читает `content/`, проверяет его и держит в памяти неизменяемый каталог. React-приложение получает всё через `/api/*`.

- Альтернатива: генератор статических сайтов (Astro, VitePress). Отклонена на этапе обсуждения: для закрепления с ИИ всё равно нужен сервер, а держать две модели контента незачем.
- Альтернатива: Vite импортирует `.md` при сборке, Python появляется позже. Отклонена: правила проверки пришлось бы писать на TypeScript, а потом переносить на сервер.
- Цена решения: без запущенного сервера справочник не читается. Локально это закрывает `mise run dev`.

### 2. Структура репозитория

```
mise.toml
backend/      pyproject.toml, uv.lock, src/turkish_grammar/, tests/
frontend/     package.json, pnpm-lock.yaml, src/
content/      README.md, sections.yaml, path.yaml, abbreviations.yaml, notation.md, topics/<id>/
docs/         topic-map-sources.md
```

Пакет бэкенда `turkish_grammar` делится на `content/` (модели, загрузка, проверка, разбор статьи и разборов по морфемам), `api/` (приложение, маршруты, схемы ответов) и `cli.py` (проверка контента, выгрузка OpenAPI). Каталог контента задаётся настройкой `CONTENT_DIR`, по умолчанию это `content/` в корне репозитория.

### 3. Инструменты и версии

- **mise**: Python 3.14, Node 26 (LTS), uv, pnpm. Точные версии закрепляются в `mise.toml`. Там же uv получает путь к Python из mise (`UV_PYTHON`), а внешний `VIRTUAL_ENV` сбрасывается: иначе uv берёт интерпретатор окружения, активированного в оболочке, а не закреплённую версию.
- **Бэкенд**: uv, FastAPI (`fastapi[standard]`), Pydantic v2, pydantic-settings, PyYAML, markdown-it-py; для разработки — ruff (линтер и форматирование), mypy в режиме strict, pytest.
- **Интерфейс**: Vite, React, TypeScript 6.0 в режиме strict, pnpm, React Router, TanStack Query, openapi-fetch, react-markdown + remark-gfm, Tailwind CSS с плагином typography; для разработки — ESLint (typescript-eslint, react-hooks), Prettier, Vitest, Testing Library, MSW, openapi-typescript.
- Берутся актуальные стабильные версии библиотек на момент реализации; их фиксируют lock-файлы.

**Отступление при реализации:** TypeScript взят версии 6.0, а не последней 7.0. Шаблон Vite теперь ставит TypeScript 7 и oxlint, но typescript-eslint поддерживает TypeScript только до 6.0, а openapi-typescript объявляет поддержку 5.x (с 6.0 проверен генерацией типов, исключение записано в `frontend/pnpm-workspace.yaml`). Линтером остался ESLint, как и решено выше. Версию можно поднять, когда оба инструмента поддержат 7.0.

**Отступление от обсуждения:** договаривались о Python 3.13. Проверка через mise показала, что сейчас актуальны ветки 3.14 и 3.15 (3.15.2 — последняя). Выбрана 3.14: это предыдущая ветка, у неё был год исправлений, тогда как 3.15 — самая новая. Совместимость библиотек с 3.14 подтвердится при установке зависимостей в задаче 1.2. Версия задаётся одной строкой в `mise.toml`, вернуться на 3.13 можно без других правок.

- Альтернатива для frontmatter: библиотека `python-frontmatter`. Отклонена: у неё нет типов для mypy strict, а отделить метаданные от текста — это десяток строк поверх PyYAML.
- Альтернатива для разбора статьи: регулярные выражения по строкам `## `. Отклонена: они ошибаются на заголовках внутри блоков кода и не находят ссылки. markdown-it-py даёт токены с номерами строк и адресами ссылок. Он используется только для разбора; в HTML текст превращает интерфейс.

### 4. Формат файлов контента

Идентификатор темы — имя её каталога. В метаданных он не дублируется, чтобы имя каталога и идентификатор не могли разойтись.

`content/topics/locative-da/topic.md`:

```markdown
---
title: Местный падеж -DA
section: nouns
level: A1
prerequisites: [vowel-harmony, consonant-assimilation]
related: [ablative-dan]
summary: Показывает, где что-то находится или когда происходит; отвечает на вопросы «где?» и «когда?».
---

## Формула

Основа + **-DA**: -da / -de / -ta / -te. См. [гармонию гласных](topic:vowel-harmony).

## Формы

| После…            | Аффикс | Пример  |
| ----------------- | ------ | ------- |
| a, ı, o, u        | -da    | okulda  |
```

`content/topics/locative-da/examples.yaml`:

```yaml
- tr: Ev*de*yim.
  ru: Я дома.
  morphemes: ev-de-yim
  gloss: дом-МЕСТ-1ЕД
- tr: Kitap masa*da*.
  ru: Книга на столе.
  note: После гласной a выбирается вариант -da.
```

Справочные файлы: `sections.yaml` — список `{id, title}`; `path.yaml` — список идентификаторов тем; `abbreviations.yaml` — список `{code, meaning}`; `notation.md` — свободный текст.

YAML читается только через `yaml.safe_load`. Модели Pydantic запрещают лишние поля (`extra="forbid"`): так опечатка в имени поля становится ошибкой, а не молча пропадает.

### 5. Шаблон статьи

«Суть» из согласованного шаблона — это поле `summary` в метаданных. Отдельного блока `## Суть` в тексте нет: одна и та же фраза показывается в списках тем, на странице заглушки и в начале статьи, и дублировать её незачем.

| Порядок | Вид          | Заголовок в интерфейсе | Откуда берётся                  |
| ------- | ------------ | ---------------------- | ------------------------------- |
| —       | суть         | (без заголовка)        | `summary` в метаданных          |
| 1       | `formula`    | Формула                | блок `## Формула` в `topic.md`  |
| 2       | `forms`      | Формы                  | блок `## Формы`                 |
| 3       | `examples`   | Примеры                | `examples.yaml`                 |
| 4       | `pitfalls`   | Подводные камни        | блок `## Подводные камни`       |
| 5       | `vs_russian` | Сравнение с русским    | блок `## Сравнение с русским`   |
| 6       | `related`    | Связанные темы         | `related` в метаданных          |

Бэкенд хранит упорядоченный список текстовых блоков (вид и заголовок) в одном месте и по нему и проверяет статью, и режет её на части. В API блок уходит как `{kind, markdown}`. Интерфейс держит полный порядок из шести блоков и рисует заголовки сам. Виды блоков попадают в TypeScript из OpenAPI, поэтому при добавлении нового вида на бэкенде интерфейс перестанет компилироваться, пока его не учтут.

Заглушка определяется по содержимому: в `topic.md` нет ни одного блока. Отдельного поля статуса нет, поэтому статус не может разойтись с текстом.

**Итог пилотных тем:** в шаблоне нет блока для значений аффикса. В теме `locative-da` они записаны подзаголовком «Что выражает» внутри блока «Формула», и это принято как правило для следующих тем; оно записано в `content/README.md`. Отдельный блок можно ввести позже отдельным изменением: список блоков задан в одном месте.

- Альтернатива: отдавать статью одним куском Markdown и резать её в интерфейсе, чтобы вставить примеры на третье место. Отклонена: знание о шаблоне оказалось бы в двух местах без проверки типами.

### 6. Разбор по морфемам

Автор пишет две параллельные строки (`morphemes` и `gloss`): слова разделены пробелами, морфемы — дефисами. Это близко к тому, как разборы пишут от руки, и не требует вложенных структур в YAML. Бэкенд превращает строки в структуру «слова → морфемы → форма и значение» и отдаёт её в API, так что интерфейс ничего не разбирает.

Правила:

- Разбирается записанная форма слова, а не исходная: `gid-iyor`, а не `git-iyor`. Благодаря этому разбор можно сверить с текстом примера.
- Сверка с `tr`: из `morphemes` убираются дефисы, из `tr` — звёздочки выделения; из обеих строк убирается пунктуация, включая апостроф (`İstanbul'da`); пробелы схлопываются; регистр приводится по турецким правилам.
- **Турецкий регистр.** `str.lower()` в Python превращает `I` в `i`, а `İ` — в `i` с отдельным знаком точки. Перед `lower()` надо заменить `I` на `ı` и `İ` на `i`. Это отдельная функция с собственными тестами.
- Часть значения считается обозначением, если в ней нет строчных букв и есть хотя бы одна заглавная (`МН`, `1ЕД`). Такие части сверяются со списком. Части составного значения разделяются точкой (`1ЕД.ПРИТ`). Всё остальное — лексическое значение (`дом`, `потому.что`).
- Это правило знает только бэкенд. В структуре разбора у морфемы есть значение целиком и его части, и каждая часть помечена, обозначение это или нет. Интерфейсу нужно оформлять обозначения иначе, чем лексические значения, и без пометки ему пришлось бы повторять правило.

Выделение звёздочками (`Ev*de*yim.`) бэкенд превращает в чистый текст и список отрезков `{text, emphasized}`; то же для `ru`.

- Альтернатива: вложенная структура в YAML (слова → морфемы → пары). Отклонена: её неудобно писать и читать, а строки дают ту же информацию.

### 7. Загрузка и проверка контента

- Контент загружается один раз, в `lifespan` приложения, и кладётся в `app.state`. Запросы читают готовый каталог из памяти.
- Проверка идёт в два прохода и собирает все ошибки. Первый проход проверяет каждый файл сам по себе: метаданные, блоки статьи, примеры. Второй проверяет связи на всём, что удалось прочитать: ссылки, маршрут, уровни, разделы, обозначения. Каждая ошибка — это пара «путь к файлу, сообщение на русском».
- Если ошибки есть, загрузка бросает исключение со всем списком, и приложение не стартует.
- Команда проверки (`mise run content:check`) вызывает ту же функцию загрузки, печатает ошибки и возвращает ненулевой код.
- Циклы пререквизитов отдельно не ищутся. Маршрут линеен и содержит каждую тему, поэтому правило «пререквизит стоит раньше» при цикле обязательно нарушится.
- Тема с испорченными метаданными остаётся известной проверке по имени каталога. Иначе одна опечатка в метаданных дала бы ещё и ошибку «такой темы нет» в каждой теме, которая на неё ссылается.
- Проверка ловит и то, что автор, скорее всего, сделал по ошибке: посторонний файл в каталоге темы (например, `example.yaml` вместо `examples.yaml`), блок статьи без текста, заголовок первого уровня, ссылку с адресом не вида `topic:<id>` и не `http(s)://`, пустое выделение `**`, код обозначения не из заглавных букв. Ссылки на темы проверяются и в `notation.md`.
- В режиме разработки сервер следит за `content/` (файлы `.md` и `.yaml`) и перезапускается при изменении. Контент небольшой, перезапуск занимает доли секунды.

### 8. Контракт API

Операции (подробности — в specs/content-api):

- `GET /api/topics` → список `TopicSummary {id, title, level, section_id, summary, is_stub}`.
- `GET /api/sections` → список `Section {id, title}`.
- `GET /api/topics/{id}` → `TopicDetail`: поля `TopicSummary`, а также `section`, `blocks`, `examples`, `prerequisites`, `related`, `previous`, `next`. Ссылки на темы — `TopicRef {id, title, is_stub}`. Морфема в разборе примера — `{form, gloss, parts: [{text, is_abbreviation}]}`.
- `GET /api/notation` → `{intro_markdown, abbreviations: [{code, meaning}]}`.
- `GET /api/openapi.json` — описание контракта; интерактивная документация — на `/api/docs`.

Имена полей в JSON — в snake_case, как их отдаёт Pydantic; слоя переименования в camelCase нет. Ошибки — в стандартном для FastAPI виде `{"detail": ...}`.

### 9. Типы между бэкендом и интерфейсом

`mise run gen:api` выгружает OpenAPI из приложения без запуска сервера (`app.openapi()`) и генерирует `frontend/src/api/schema.d.ts` через openapi-typescript. Контент для этого не нужен, потому что он загружается только в `lifespan`. Файл с типами хранится в git. `mise run check` генерирует его заново и падает, если он отличается от сохранённого. Запросы идут через openapi-fetch, который типизирован по этой схеме.

- Альтернатива: описывать типы вручную в TypeScript. Отклонена: модели описывались бы дважды и расходились бы молча.

### 10. Интерфейс

- **Маршруты**: `/` (главная), `/topics/:id` (тема), `/notation` (обозначения), всё остальное — «Страница не найдена». Ответ 404 от API на странице темы показывает ту же страницу «не найдено».
- **Каркас**: шапка, панель навигации и область содержимого. Ниже ширины `lg` панель превращается в выдвижную и открывается кнопкой в шапке.
- **Данные**: TanStack Query. Список тем и разделы загружаются один раз и используются и главной, и панелью навигации. Контент меняется только при перезапуске сервера, поэтому `staleTime` большой.
- **Группировка в панели** хранится в `localStorage`.
- **Markdown**: react-markdown + remark-gfm, без плагинов для сырого HTML. По умолчанию react-markdown вырезает адреса с незнакомой схемой, поэтому `urlTransform` надо переопределить так, чтобы он пропускал `topic:`. Собственный компонент ссылки превращает `topic:<id>` в ссылку маршрутизатора. Таблицы оборачиваются в контейнер с горизонтальной прокруткой.
- **Турецкий текст** примеров и разборов получает атрибут `lang="tr"`. К нему не применяется `text-transform`: без правильного языка браузер портит `i` и `ı`.
- **Оформление**: Tailwind, typography для текста статей, шрифт Inter (variable, подключается из пакета, а не с внешнего CDN) — в нём есть и кириллица, и турецкие буквы. Обозначения в разборах набираются уменьшенными заглавными.
- **Шрифт берётся из официального пакета `inter-ui`** и включает варианты букв `cv05` и `cv08`: строчная l с хвостиком, заглавная I с засечками. Без них `l` и `I` в записи аффиксов (`-lAr`, `-Il`) неотличимы. В сборке `@fontsource-variable/inter` эти варианты вырезаны, поэтому она не подошла.
- **Запись аффикса не рвётся при переносе строки** в названиях и сути тем: иначе браузер оставляет дефис в конце строки, а остаток уносит на следующую.
- В разработке Vite проксирует `/api` на бэкенд (`127.0.0.1:8000`), поэтому CORS не нужен, а интерфейс везде использует относительные адреса.

### 11. Тесты

- **Бэкенд**: pytest. На каждое правило проверки — тесты на маленьком контенте, который собирается во временном каталоге; сценарии из specs/content-model переносятся в тесты один к одному. API проверяется через `TestClient` на таком же контенте. Настоящий `content/` проверяет `content:check`.
- **Интерфейс**: Vitest + Testing Library, запросы подменяет MSW. Покрываются порядок блоков на странице темы, отображение примера и разбора, группировки панели, заглушка, состояния загрузки, ошибки и «не найдено».
- Вёрстка на узком экране проверяется вручную в браузере.

### 12. Задачи mise

| Задача              | Что делает                                                                   |
| ------------------- | ---------------------------------------------------------------------------- |
| `install`           | `uv sync` и `pnpm install`                                                   |
| `dev`               | запускает `dev:backend` и `dev:frontend` параллельно                         |
| `dev:backend`       | сервер API с перезапуском при изменении кода и контента                      |
| `dev:frontend`      | Vite с прокси на API                                                         |
| `content:check`     | проверка контента без запуска сервера                                        |
| `gen:api`           | выгрузка OpenAPI и генерация TypeScript-типов                                |
| `lint` / `format`   | ruff, ESLint, Prettier                                                       |
| `typecheck`         | mypy и `tsc`                                                                 |
| `test`              | pytest и Vitest                                                              |
| `check`             | `lint`, `typecheck`, `test`, `content:check` и проверка свежести типов API   |

### 13. Как строится карта тем

- **Источники** (окончательный список — в `docs/topic-map-sources.md`): содержание учебных комплексов Yedi İklim (Yunus Emre Enstitüsü), İstanbul — Yabancılar için Türkçe и Yeni Hitit по уровням A1–B2; программа Türkiye Maarif Vakfı с уровнями CEFR; справочная грамматика Göksel, Kerslake «Turkish: A Comprehensive Grammar» для проверки полноты. Издательства оглавления учебников не публикуют, поэтому их содержание взято из научных статей и университетских программ.
- **Метод**: уровень темы берётся из учебных комплексов (если они расходятся, берётся более ранний). Затем оглавление справочной грамматики проходится целиком, и каждое явление либо находится на карте, либо получает уровень и тему, либо попадает в список исключений с причиной.
- **Уточнения метода, которые понадобились при составлении карты:**
  - если комплексы тему не называют или относят выше B2, уровень берётся из программы Maarif;
  - если темы нет ни в комплексах, ни в программе, но она есть в справочной грамматике, уровень назначается по смежным темам; такие темы перечислены в `docs/topic-map-sources.md` отдельным списком;
  - тема не может стоять раньше своего пререквизита: если источник ставит её раньше, она получает уровень пререквизита (так `converb-ken` перешла с A1 на A2);
  - явление, которое все источники относят выше B2, записывается в исключения.
- **Идентификаторы**: английские, в kebab-case, только ASCII; аффикс пишется латиницей без диакритики: `vowel-harmony`, `plural-lar`, `locative-da`, `past-di`, `cases-overview`. Идентификатор входит в адрес страницы, поэтому его не меняют после появления.
- **Названия**: русское название явления и аффикс в записи с заглавными буквами для чередующихся звуков: «Местный падеж -DA».
- **Разделы** — пятнадцать: Фонетика и письмо; Существительное; Местоимения; Прилагательные и наречия; Числительные; Послелоги; Именное сказуемое; Глагол: основа, отрицание, составные формы; Времена глагола; Наклонения и модальность; Залоги; Причастия, деепричастия и имена действия; Союзы и частицы; Синтаксис; Словообразование. К черновику из тринадцати добавлены два: общие правила глагола не относятся ни к временам, ни к наклонениям, а союзы и частицы — не синтаксис предложения.
- **Объём**: 227 тем — A1 76, A2 54, B1 56, B2 41. Оценка была 150–200 тем и около 50 на A1. Больше вышло из-за правила «берётся более ранний уровень»: каждый комплекс вводит часть материала раньше остальных. Уровни, которые держатся на одном комплексе, перечислены в `docs/topic-map-sources.md`.
- **Пилотные темы**: `vowel-harmony`, `plural-lar`, `locative-da`. Они проверяют шаблон на трёх разных типах материала: правило фонетики без аффикса, простой аффикс и аффикс с двумя чередованиями.

## Risks / Trade-offs

- [Грамматические ошибки в текстах, написанных ИИ] → Пилотные темы вычитывает пользователь. Разборы проверяются автоматически на согласованность с текстом примера и на список обозначений. Источники карты записаны. Статусы «проверено» отложены сознательно.
- [Шаблон окажется тесным: в нём нет блока для описания употребления] → Три пилотные темы пишутся именно для проверки шаблона. Список блоков задан в одном месте на бэкенде и одной константой в интерфейсе, новый блок добавляется без правки уже написанных тем.
- [Карта тем окажется неполной] → Сверка с оглавлением справочной грамматики и список исключений. Добавить тему позже дёшево: новый каталог и строка в маршруте, а проверка не даст забыть про маршрут.
- [Источники недоступны в сети целиком] → Используются доступные оглавления и программы. Что взять не удалось, записывается в `docs/topic-map-sources.md`. Карту вычитывает пользователь.
- [Неудачный идентификатор темы закрепляется в адресе] → Правила именования заданы до составления карты, идентификаторы проходят вычитку вместе с картой. Редиректов нет, поэтому переименование позже сломает сохранённые ссылки.
- [Строгая проверка мешает писать: одна ошибка останавливает сервер] → Отчёт содержит все ошибки сразу с файлом и причиной. `content:check` работает без сервера. В режиме разработки сервер сам поднимается после исправления.
- [Справочник не открывается без запущенного сервера] → Локально хватает `mise run dev`. Интерфейс использует относительные адреса `/api`, поэтому любой будущий хостинг с серверными функциями подойдёт без переделки.
- [Генерируемый файл типов расходится с бэкендом] → `mise run check` генерирует его заново и падает при расхождении.
