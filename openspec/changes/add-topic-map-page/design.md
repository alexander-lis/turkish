# Design

## Context

Мотивация и состав изменения — в proposal.md. Изменение применяется после `add-topic-graph`. От него нужны:

- запрос `GET /api/graph`: все темы в порядке учебного маршрута, связи видов «пререквизит», «тема обзора» и «связанная тема», различения;
- признак обзора у темы;
- разделы из `GET /api/sections` — они уже лежат в кеше интерфейса для панели навигации.

Что рисовать, по данным на 13 ноября 2026 года: 227 тем в 15 разделах (от 7 до 46 тем в разделе), 13 обзоров, 467 пререквизитов, около 140 связанных пар после снятия повторов, 38 различений на уровне A1.

Состояние интерфейса:

- `Layout` даёт шапку, панель навигации и колонку содержимого шириной `max-w-3xl`;
- страницы подключены в `AppRoutes` одним маршрутом-каркасом; весь код интерфейса идёт одним бандлом;
- выбранную группировку панель навигации хранит в `localStorage`;
- тесты — Vitest и Testing Library в jsdom, сеть подменяет msw.

Ограничения:

- На карте вдвое больше связей, чем тем. Нарисованные все сразу, они закрывают дерево.
- Дерево из 227 листьев при строке в 36 пикселей — около 8000 пикселей в высоту одной колонкой и около 4000, если разделить его на две стороны. В экран целиком оно помещается только в нечитаемом масштабе.
- Отметки о пройденных темах появятся позже и лягут на те же узлы.

## Goals / Non-Goals

**Goals:**

- Читатель с первого экрана видит справочник целиком: разделы и размер каждого.
- У любой темы за одно нажатие видны все её связи и переход к каждой из них.
- Раскладка предсказуема: одна и та же карта при каждом открытии, раздел не меняет сторону при сворачивании.
- Остальные страницы не платят за карту ни размером бандла, ни временем загрузки.
- Логика карты — чистые функции, которые тестируются без браузера.

**Non-Goals:**

- Узлы не перетаскиваются, своя раскладка не сохраняется.
- Раскладка не уменьшает число пересечений перекрёстных линий: они рисуются поверх готового дерева.
- Поиска по карте нет: найти тему по названию помогает панель навигации, а ссылка «Показать на карте» ведёт с её страницы.
- Отметок о пройденных темах нет. Решение 12 только оставляет для них место.
- Карта не заменяет списки: главная страница и панель навигации остаются.

## Decisions

### 1. Страница называется «Карта тем» и живёт по адресу `/map`

«Карта тем» — термин глоссария: полный перечень тем справочника. Страница показывает именно его, только деревом и со связями. Второе название для того же не вводится: слово «майндмапа» уходит в синонимы, которых избегаем.

### 2. Каркас карты — дерево, связи графа лежат поверх него

Граф тем — не дерево: тема входит в два обзора, а обзор отрицания стоит в разделе «Синтаксис», тогда как его темы — в двух других разделах. Карте нужен каркас, в котором у каждой темы одно место. Им служит раздел: он есть у каждой темы и ровно один.

Родитель узла:

1. у раздела — корень;
2. у темы — первый по учебному маршруту видимый обзор **её раздела**, в который она входит;
3. иначе — её раздел.

То же правило действует для обзора, который входит в другой обзор.

Связь «тема обзора», которая не стала веткой дерева, рисуется отдельной линией и видна всегда: это часть строения карты, и таких связей мало. Пример: `past-di` стоит под `tense-overview` в разделе «Времена глагола» и соединён линией с `personal-endings-overview` из раздела о глаголе.

- Альтернатива: обзоры как корни вместо разделов. Отклонена: три четверти тем не входят ни в один обзор.
- Альтернатива: раскладка графа без каркаса (силовая или послойная по пререквизитам). Отклонена: 467 пререквизитов дают клубок, а место темы меняется от каждой новой связи. Послойный вид по пререквизитам — это другой взгляд, учебный маршрут, и он уже показан списком.

### 3. Раскладка — двустороннее дерево, считает `d3-hierarchy`

Корень стоит в центре, разделы расходятся вправо и влево, темы идут строками. Это привычный вид интеллект-карты, и названия тем в нём читаются горизонтально.

- Положения считает `tree()` из `d3-hierarchy` с фиксированным размером узла, отдельно для каждой стороны; левая сторона отражается по горизонтали.
- Разделы делятся между сторонами один раз, по полному числу тем: граница проходит там, где стороны ближе всего к равным. При текущем контенте справа девять разделов от «Фонетики и письма» до «Времён глагола» (111 тем), слева шесть — от «Наклонений и модальности» до «Словообразования» (116 тем). Сворачивание и фильтр уровней сторону раздела не меняют.
- Ширина узла фиксирована, длинное название обрезается многоточием; целиком оно стоит в подсказке узла и в панели темы.
- Раскладка — чистая синхронная функция: одинаковый вход даёт одинаковые координаты.

- Альтернатива: `elkjs`. Отклонена: он нужен графам общего вида, а каркас здесь — дерево. `elkjs` асинхронный и тяжёлый (больше мегабайта), `d3-hierarchy` — синхронный и на два порядка меньше.
- Альтернатива: радиальное дерево. Отклонена: 227 подписей по окружности либо наклонены, либо наезжают друг на друга.
- Альтернатива: разделы-карточки с темами в несколько столбцов. Отклонена: карточки занимают меньше места, но теряют дерево — обзор перестаёт быть узлом, от которого расходятся его темы.

### 4. Холст — React Flow

`@xyflow/react` даёт перемещение, масштаб колесом и жестами, кнопки масштаба, узлы-компоненты React и линии со стрелками. Узлы и линии передаются готовыми: перетаскивание и соединение узлов выключены.

- Узел — компонент с кнопкой внутри. Фокус получает кнопка, а собственный фокус обёртки React Flow выключен, иначе у узла было бы две остановки Tab. Имя кнопки для программ чтения с экрана включает название темы, уровень и пометки «обзор» и «не написано».
- Виды узлов: корень, раздел, тема. Обзор — тема с другим оформлением.
- Виды линий различаются начертанием, а не только цветом: ветка дерева — тонкая сплошная; пререквизит — сплошная со стрелкой; различение — пунктир; связанная тема — точки; связь с обзором вне ветки — длинный штрих.
- Уровень показан подписью на узле и цветной полосой: четыре тона, которые объясняют условные обозначения.

- Альтернатива: свой SVG и `d3-zoom`. Отклонена: пришлось бы заново писать жесты, фокус и отсечение невидимого.
- Альтернатива: Cytoscape.js. Отклонена: узлы там рисуются на canvas, а не компонентами React, — подписи, пометки и доступность пришлось бы делать отдельным слоем.

### 5. Перекрёстные связи: у выбранной темы — все, остальное — слоями

- Выбранная тема показывает все свои связи независимо от слоёв; несвязанные узлы приглушаются.
- Три слоя включают связи одного вида по всей карте: «Пререквизиты», «Различения», «Связанные темы».
- При первом открытии включён только слой «Различения»: их десятки, а не сотни, и это связи, которых не видно ни в одном списке.

Линия к скрытой теме не рисуется: скрытый узел не имеет места на карте. Связь при этом остаётся в панели темы, и нажатие на неё раскрывает тему (решение 8).

- Альтернатива: рисовать линию к свёрнутому разделу скрытой темы. Отклонена: у раздела накапливались бы десятки линий без подписи.

### 6. Различение рисуется попарными линиями

Различение трёх тем — три линии одного вида. Название различения читатель видит в панели темы. Подписи на самих линиях не ставятся: на карте они перекрывали бы узлы.

### 7. При первом открытии разделы свёрнуты

Развёрнутая карта в экран не помещается: при масштабе «всё на экране» буквы меньше четырёх пикселей. Свёрнутая показывает корень и 15 разделов с числом тем — справочник целиком и читаемо. Дальше читатель разворачивает нужные разделы или все сразу, и этот набор сохраняется (решение 8).

При сворачивании и разворачивании узел раздела остаётся на том же месте экрана: окно просмотра сдвигается на столько же, на сколько раскладка сдвинула узел.

- Альтернатива: открывать карту развёрнутой и вписанной в экран. Отклонена как умолчание: первое впечатление — серое полотно без единого читаемого слова. Вид доступен одним действием «Развернуть все» и запоминается.

Это умолчание — предмет контрольной точки с пользователем (tasks.md, группа 6).

### 8. Где хранится состояние вида

| Что | Где | Почему |
| --- | --- | --- |
| выбранная тема | адрес: `/map?topic=<id>` | на тему на карте можно дать ссылку; работает кнопка «Назад» |
| включённые уровни и слои, развёрнутые разделы | `localStorage`, один ключ | это привычки читателя, а не адрес; тем же способом панель навигации хранит группировку |
| положение и масштаб окна | память страницы | после перезагрузки карта вписывается в экран или показывает выбранную тему |

Адрес главнее сохранённых настроек: если тема из адреса скрыта свёрнутым разделом или выключенным уровнем, раздел разворачивается, уровень включается, и это изменение сохраняется. Так же раскрывается тема, выбранная нажатием в панели.

Идентификатор в адресе, которого нет в графе, просто не выбирает ничего. Раздел, которого больше нет в контенте, из сохранённых настроек отбрасывается при чтении.

### 9. Панель темы строится из графа, без запроса темы

Название, уровень, раздел, суть и пометки есть в графе. Списки связей считает функция от графа и идентификатора темы:

| Подпись | Связи графа |
| --- | --- |
| Пререквизиты | «пререквизит», где тема — конец |
| Нужна для | «пререквизит», где тема — начало |
| Входит в обзор | «тема обзора», где тема — конец |
| Темы обзора | «тема обзора», где тема — начало |
| Не путать | различения, в темы которых она входит: название и остальные темы |
| Связанные темы | «связанная тема» с любой стороны |

Внутри списка темы идут в порядке учебного маршрута. Длинный список прокручивается внутри панели: у `vowel-harmony` десятки тем в «Нужна для».

Список «Связанные темы» в панели может отличаться от одноимённого блока на странице темы: граф считает связь ненаправленной и убирает повторы по своему правилу. Это следствие решений `add-topic-graph`, а не ошибка.

Статью и примеры панель не показывает: за ними ведёт ссылка на страницу темы.

### 10. Карта занимает всю область под шапкой

Колонка `max-w-3xl` карте не подходит. У `Layout` появляется широкий вид: панель навигации скрыта и открывается кнопкой при любой ширине экрана, как сейчас на узком; область содержимого без полей и ограничения ширины, высотой в экран за вычетом шапки. Маршрут `/map` использует широкий вид, остальные — прежний.

На узком экране панель темы открывается снизу и занимает не больше половины высоты, переключатели слоёв и уровней собраны в сворачиваемый блок поверх карты.

### 11. Код карты грузится отдельно

Страница карты подключается через `React.lazy`: React Flow, `d3-hierarchy` и стили холста попадают в отдельный файл сборки и загружаются при первом открытии `/map`. Пока файл грузится, показан тот же индикатор загрузки, что и при запросах.

### 12. Логика — чистые функции в `src/lib/`

| Функция | Вход | Выход |
| --- | --- | --- |
| дерево карты | граф, разделы, включённые уровни, развёрнутые разделы | дерево видимых узлов по правилу решения 2 и связи с обзорами вне ветки |
| раскладка | дерево, стороны разделов | координаты узлов и ветки дерева |
| линии | граф, видимые темы, слои, выбранная тема | перекрёстные линии с видом и признаком «относится к выбранной» |
| связи темы | граф, идентификатор | списки для панели по решению 9 |
| настройки вида | строка из `localStorage`, разделы | уровни, слои, развёрнутые разделы; чтение с отбрасыванием неизвестного |

Страница только соединяет их с React Flow, адресом и хранилищем. Тесты функций не требуют холста.

Компонентным тестам страницы нужны заглушки окружения, которых нет в jsdom: `ResizeObserver`, `DOMMatrixReadOnly`, размеры элементов. Их перечисляет руководство React Flow по тестированию; они добавляются в `src/test/setup.ts`.

Узел темы получает данные одним объектом. Отметка о пройденной теме позже станет ещё одним его полем и ещё одним знаком на узле; цвет полосы уже занят уровнем, поэтому отметка будет значком, а не цветом.

## Risks / Trade-offs

- [Развёрнутая карта слишком высокая] → Разделы свёрнуты по умолчанию; фильтр уровней оставляет один уровень — у A1 это 76 тем; «Показать всё» возвращает общий вид.
- [Включённый слой пререквизитов закрывает дерево] → Слой выключен по умолчанию; линии слоя тонкие и полупрозрачные, а линии выбранной темы — плотные.
- [Длинные названия обрезаны] → Полное название в подсказке и в панели темы; ширина узла подбирается на контрольной точке.
- [React Flow плохо работает в jsdom] → Вся логика в чистых функциях; компонентные тесты проверяют только связку: узлы на месте, выбор, панель, адрес. Жесты и вид проверяются в браузере.
- [Сотни кнопок-узлов делают обход клавишей Tab долгим] → Свёрнутые разделы сокращают обход до развёрнутого; панель темы даёт переход по связям; панель навигации остаётся вторым путём к любой теме.
- [Новые зависимости увеличивают сборку] → Отдельный файл сборки; проверка — в отчёте сборки основной файл не содержит React Flow.
- [`add-topic-graph` изменит форму ответа до архивации] → Изменения применяются по очереди; задача 1.2 начинает с сверки с актуальной схемой `GET /api/graph`.

## Migration Plan

Данных и API изменение не трогает. Страница добавляется новым маршрутом, существующие адреса не меняются. Откат — возврат коммитов.

## Open Questions

- Нужна ли на карте мини-карта для быстрых переходов по высокой развёрнутой карте. Решается после контрольной точки: добавить её — одна строка, состав изменения она не меняет.
