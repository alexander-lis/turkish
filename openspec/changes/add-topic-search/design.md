# Design

## Context

Мотивация и состав изменения — в proposal.md, поведение — в specs/. Что есть сейчас и что из этого следует:

- Сервер держит весь контент в памяти (`Catalog`) и строит из него производные структуры при старте: граф тем — в `lifespan`, рядом с каталогом.
- Текст статьи хранится блоками в Markdown (`ArticleBlock.markdown`); разбирает его только `content.article` через markdown-it-py. Текст примера уже лежит без служебных звёздочек в `MarkedText.text`.
- Корпус ограничен картой тем: 227 тем, из них 76 написаны. Статьи написанных тем занимают около 300 КБ, турецкий текст и перевод 753 примеров — 52 КБ, примечания — 22 КБ. Когда будут написаны все темы, выйдет около 1,2 МБ.
- Название темы содержит формулу аффикса по правилам `content/notation.md`: заглавные буквы A, I, D, C, G, K чередуются, скобки отмечают необязательный звук, косая черта — варианты. Как отличить формулу от слова, описано в `content/README.md`: запись начинается с дефиса либо содержит скобку, косую черту или заглавную букву после строчной.
- Окно темы на карте — модальный `<dialog>`: фон, фокус и Escape даёт браузер. В jsdom `showModal` и `close` заменены заглушками; `scrollIntoView` в jsdom нет.
- Блоки страницы темы уже имеют идентификаторы `block-<вид>` (`TopicArticle`), но страница к ним не прокручивается: содержимое приходит после загрузки, когда браузер якорь уже обработал. Шапка закреплена сверху и закрывает 56 пикселей.
- Интерфейс читает данные через TanStack Query с `staleTime: Infinity`: контент меняется только при перезапуске сервера.
- typescript-eslint `strictTypeChecked` запрещает устаревшие API, в том числе `navigator.platform`.

## Goals / Non-Goals

**Goals:**

- Список обновляется на каждую букву без запроса к серверу.
- Правила поиска — чистые функции без React и без DOM, покрытые модульными тестами по сценариям specs/topic-search.
- Оболочка окна поиска не знает о темах: её можно переписать на библиотеке или дать ей второй источник строк, не меняя логику поиска и связку с темами.
- Одна разметка Markdown — один разборщик: текст без разметки делает сервер тем же markdown-it-py, которым проверяет статьи.

**Non-Goals:**

- Нечёткий поиск с опечатками и поиск в неверной раскладке клавиатуры.
- Сжатие ответа с индексом: справочник работает локально.
- Группы строк, строки-действия и режимы окна: их добавит изменение, которому они нужны.
- Выделение совпадения в названии темы: по формуле аффикса выделять в названии нечего, а совпадение с названием видно и так.
- Подъём точного совпадения с диакритикой над совпадением после свёртки.

## Decisions

### 1. Ищет браузер по индексу, который сервер отдаёт один раз

`GET /api/search-index` возвращает все темы с текстами; интерфейс запрашивает его при первом открытии окна и держит в кеше запросов. Поиск — вызов чистой функции на каждое изменение запроса.

Корпус не вырастет больше карты тем, поэтому индекс всегда помещается в браузере, а проход по 1,2 МБ заранее свёрнутых строк укладывается в единицы миллисекунд.

- Альтернатива: `GET /api/search?q=` на каждую букву. Отклонена: нужны отмена устаревших ответов и удержание прошлого списка, а выигрыш — только размер одного ответа.
- Альтернатива: названия искать в браузере, тексты — на сервере. Отклонена: свёртка и порядок выдачи жили бы в двух языках.

### 2. Поисковый индекс строит сервер из каталога

Новый модуль `content.search_index`: `build_search_index(catalog)` возвращает кортеж записей в порядке учебного маршрута. Индекс строится в `lifespan` после графа тем и лежит в `app.state`.

Форма записи (в API — схемы с теми же именами):

```
SearchTopic    id, title, level, section_id, summary, is_stub, is_overview   как TopicSummary
               section_title: str
               blocks: [SearchBlock]        пусто у заглушки
               examples: [SearchExample]    пусто у заглушки
SearchBlock    kind: BlockKind, lines: [str]
SearchExample  tr: str, ru: str, note: str | None
```

Название раздела лежит в записи, чтобы окну поиска хватало одного запроса.

Текст без разметки делает новая функция `plain_lines(markdown)` в `content.article` — единственном модуле, который знает markdown-it-py. Она идёт по токенам: каждый абзац, пункт списка, подзаголовок и строка таблицы дают одну строку; внутри строки берётся содержимое текстовых токенов и кода, мягкий перенос становится пробелом, ячейки таблицы соединяются пробелом. Адреса ссылок и знаки разметки в токены текста не попадают, поэтому `kitap**lar**` даёт `kitaplar` без отдельного правила.

Все строки индекса приводятся к NFC: поиск в браузере сравнивает символ с символом.

- Альтернатива: отдавать Markdown и снимать разметку в браузере. Отклонена: второй разборщик Markdown с другими правилами, и запрос находил бы адреса ссылок там, где разборщики расходятся.
- Альтернатива: строить индекс в `api.routes` на каждый запрос. Отклонена: 76 статей пришлось бы разбирать заново при каждом открытии окна, а граф тем уже задаёт образец — производное от каталога живёт в `content` и строится при старте.

### 3. Свёртка для сравнения — посимвольная

`foldText` в `src/lib/searchFold.ts` заменяет каждый символ одним символом, поэтому позиция совпадения в свёрнутой строке равна позиции в исходной, и фрагмент с выделением вырезается без пересчёта.

- `İ`, `I`, `ı`, `î` → `i`; `ç` → `c`; `ğ` → `g`; `ö` → `o`; `ş` → `s`; `ü`, `û` → `u`; `â` → `a`; `ё` → `е`; то же для заглавных.
- Остальные символы — `toLowerCase()`, если результат той же длины, иначе символ остаётся как есть.

`İ` заменяется явно и до приведения к нижнему регистру: `"İ".toLowerCase()` в JavaScript даёт два символа.

Запрос приводится к NFC, сворачивается и делится на слова по пробелам; у слова запроса и у слова названия срезаются дефисы по краям, так что `-da` и `da` — один запрос.

### 4. Формула аффикса разворачивается в варианты

`src/lib/affixFormula.ts` делает две вещи:

- узнаёт формулу среди слов названия по правилу из `content/README.md`;
- разворачивает её в список вариантов: A → a, e; I → ı, i, u, ü; D → d, t; C → c, ç; G → g, k; K → k, ğ; `(x)` → x или ничего; `(x/y)` → x, y или ничего; косая черта вне скобок делит запись на отдельные формулы. Строчные буквы остаются как есть.

Варианты сворачиваются `foldText` и становятся дополнительными «словами» названия. Самая длинная формула контента, `-DIğIndAn`, даёт 64 варианта до свёртки; после свёртки их меньше.

Развёртка порождает и сочетания, которых гармония гласных не допускает (`acek`). Они безвредны: читатель их не введёт.

- Альтернатива: сворачивать обе стороны в классы чередований (a и e → A). Отклонена: строчная `e` в `-(y)ken` тоже свернулась бы, и `kan` находил бы эту тему — а по `notation.md` строчные буквы не чередуются никогда.
- Альтернатива: поле с вариантами аффикса в метаданных темы. Отклонена: варианты выводятся из названия, а поле пришлось бы поддерживать руками в 227 темах.

### 5. Ступени совпадения и порядок

Слово запроса получает в теме лучшую из ступеней:

| Ступень | Где и как совпало |
|---|---|
| 1 | слово названия или вариант формулы равны слову запроса |
| 2 | слово названия или вариант формулы начинаются со слова запроса |
| 3 | слово запроса стоит внутри слова названия или варианта формулы |
| 4 | суть |
| 5 | пример: турецкий текст, перевод или примечание |
| 6 | текст блока статьи |

На ступенях 4–6 участвуют слова от двух символов. Ступень темы — худшая из ступеней слов запроса; тема без хотя бы одного слова в выдачу не попадает. Порядок выдачи — по ступени, затем по месту в учебном маршруте, то есть по порядку записей индекса.

Формула стоит на тех же ступенях, что и обычное слово названия. Поэтому `de` ставит «Местный падеж -DA» (вариант равен запросу, ступень 1) выше названия со словом *demek* (начало слова, ступень 2).

`src/lib/search.ts` сворачивает индекс один раз (`prepareIndex`: слова названия с вариантами формул, свёрнутые суть, строки примеров и блоков) и ищет по подготовленному (`searchTopics`). Результат — найденные темы по порядку, обрезанные до двадцати, и общее число найденных.

### 6. Строка результата: место совпадения и фрагмент

Место, которое показывает строка, задаёт ступень темы:

- ступени 1–3 — название раздела, адрес `/topics/<id>`;
- ступень 4 — подпись «Суть» и фрагмент сути, адрес `/topics/<id>`;
- ступень 5 — подпись «Пример», турецкий текст и рядом перевод; если совпало только примечание, вместо перевода стоит фрагмент примечания; адрес `/topics/<id>#block-examples`;
- ступень 6 — заголовок блока из `TEMPLATE` и фрагмент строки, адрес `/topics/<id>#block-<вид>`.

Из строк нужного места берётся первая, в которой есть все слова запроса, а если такой нет — первая со словом, которое определило ступень.

Фрагмент — отрезки вида «текст, выделен или нет», как `TextSegment` в ответе о теме. Строка длиннее 120 символов обрезается окном вокруг первого совпадения по границам слов, с многоточиями. Выделяются все вхождения всех слов запроса внутри окна; пересекающиеся выделения сливаются.

Адрес блока собирает новая функция в `src/lib/site.ts`.

### 7. Три части интерфейса и граница между ними

```
 Layout
   |
 SearchLauncher     кнопка в шапке, сочетание клавиш, открыто или закрыто
   |
 TopicSearch        запрос -> индекс -> searchTopics -> строки тем; куда ведёт выбор
   |          \
 SearchDialog   lib/search.ts, searchFold.ts, affixFormula.ts
 окно, поле, список, клавиши, ARIA
```

`SearchDialog` — оболочка. Она получает данные и ничего не знает о темах, индексе, API и адресах тем:

```ts
interface SearchRow {
  id: string;
  href: string;
}

interface SearchDialogProps<Row extends SearchRow> {
  open: boolean;
  onClose: () => void;
  label: string;
  placeholder: string;
  query: string;
  onQueryChange: (query: string) => void;
  rows: readonly Row[];
  renderRow: (row: Row) => ReactNode;
  onSelect: (row: Row, target: "same-tab" | "new-tab") => void;
  /** Вместо списка, когда строк нет: подсказка, загрузка, ошибка, «Ничего не найдено». */
  status: ReactNode;
  /** Строка под списком; она же объявляется программам чтения с экрана. */
  summary: string;
}
```

Правила границы:

- Строки приходят данными и уже упорядочены. Оболочка не фильтрует и не сортирует: активная строка — номер в списке.
- Адрес строки лежит в данных (`href`), а не в разметке, которую рисует связка. Оболочка сама оборачивает строку в ссылку, а версия на библиотеке, где строка — не ссылка, сможет перейти по адресу из обработчика.
- Что значит выбор, решает связка: `TopicSearch` переходит по адресу и закрывает окно либо открывает новую вкладку и оставляет окно открытым.
- Сочетание клавиш и кнопка живут в `SearchLauncher`: библиотеки вроде `cmdk` их не дают, и при замене оболочки они не меняются.
- Компонентные тесты оболочки находят элементы по ролям `combobox`, `listbox` и `option`, а не по классам и структуре.

Плоский список `rows` вместо групп выбран намеренно: группа сейчас была бы одна, без заголовка. Группы и строки-действия появятся вместе со вторым источником строк; для оболочки это новое поле в данных, для `TopicSearch` и `lib/search.ts` — ничего.

- Альтернатива: `cmdk`. Отклонена пользователем на этом этапе: его фильтр и его диалог пришлось бы выключить, а строки-ссылки вкладывать в строки-`div`; остаётся управление активной строкой ценой пяти пакетов. Граница выше оставляет замену делом одного файла.
- Альтернатива: составные компоненты (`<Search.Input>`, `<Search.Item>`), как в `cmdk`. Отклонена: порядок строк пришлось бы выяснять по DOM, а это и есть сложная часть такой библиотеки.

### 8. Оболочка: `<dialog>` и поле со списком

Окно — модальный `<dialog>` с `showModal()`, как окно темы: неактивный фон, удержание фокуса, Escape и возврат фокуса даёт браузер. Поверх открытого окна темы второе модальное окно ложится само — оба в верхнем слое. Нажатие на затемнение определяется так же, как в `MapTopicDialog`; этот приём выносится в общий хук, которым пользуются оба окна.

Разметка — образец «поле со списком» из руководства WAI-ARIA:

- поле: `role="combobox"`, `aria-expanded`, `aria-controls`, `aria-autocomplete="list"`, `aria-activedescendant` с идентификатором активной строки;
- список: `role="listbox"`; строка: `<a role="option" aria-selected tabIndex={-1} href>`;
- `summary` стоит в области с `aria-live="polite"`.

Фокус всё время в поле. Поведение:

- стрелки вниз и вверх двигают активную строку и останавливаются на краях списка; у события отменяется действие по умолчанию, чтобы курсор в поле не прыгал;
- при смене `rows` активной становится первая строка;
- активная строка после движения стрелками прокручивается в видимую область: `scrollIntoView({ block: "nearest" })`;
- строку делает активной `pointermove` над ней, а не `mouseenter`: иначе список, который прокручивается под неподвижным указателем, перехватывал бы выбор у клавиатуры;
- Enter вызывает `onSelect(row, "same-tab")`, Enter с Cmd или Ctrl — `"new-tab"`; Enter во время набора через редактор метода ввода (`isComposing`) пропускается;
- обычное нажатие на строку — `onSelect(row, "same-tab")` с отменой перехода по ссылке; нажатие с клавишей-модификатором или средней кнопкой оболочка не трогает, и браузер сам открывает `href` в новой вкладке.

Запрос живёт в `TopicSearch` и сбрасывается при закрытии окна.

### 9. Сочетание клавиш и кнопка в шапке

`SearchLauncher` слушает `keydown` на `window`: клавиша определяется по `event.code === "KeyK"`, а не по `event.key`, вместе с `metaKey` или `ctrlKey` и без Alt и Shift. По `event.key` при русской раскладке пришла бы «л». Действие браузера по умолчанию отменяется: в Firefox и Chrome на Windows и Linux Ctrl+K ставит фокус в строку поиска браузера. Сочетание переключает окно: открытое закрывает.

Оба модификатора принимаются на любой системе: различать системы ради этого незачем, а других текстовых полей, где Ctrl+K на macOS что-то значит, в интерфейсе нет.

Кнопка выглядит как поле: значок лупы, слово «Поиск» и подсказка сочетания — `⌘K` на macOS, `Ctrl K` на остальных. Систему определяет `navigator.userAgent`: `navigator.platform` устарел, и линтер его не пропустит. На экране шириной меньше 640 пикселей (до точки `sm`) от кнопки остаётся значок с доступным именем «Поиск».

### 10. Загрузка индекса

`searchIndexQuery` в `queries.ts` включается, когда окно открыто (`enabled`), и дальше живёт в кеше: повторное открытие и переход между страницами индекс не перезапрашивают. `TopicSearch` готовит индекс к поиску (`prepareIndex`) один раз на загруженные данные.

Состояния окна собирает `TopicSearch` и передаёт в `status`: подсказка с примерами запросов при пустом запросе, индикатор загрузки, сообщение об ошибке с кнопкой «Повторить» (`refetch`), «Ничего не найдено».

- Альтернатива: грузить индекс вместе со страницей. Отклонена: 0,4–1,2 МБ на каждое открытие справочника ради окна, которое могут не открыть. Если первая загрузка на практике заметна, индекс можно запрашивать заранее по наведению на кнопку.

### 11. Страница темы прокручивается к блоку из адреса

`TopicPage` после загрузки темы и при каждой смене якоря находит элемент с идентификатором из адреса и вызывает `scrollIntoView()`. Заголовки блоков получают `scroll-margin-top` на высоту шапки с запасом. Если элемента нет, страница остаётся в начале.

Прокрутка живёт в `TopicPage`, а не в `TopicArticle`: тот же `TopicArticle` показывает окно темы на карте, где якорь адреса к нему не относится.

### 12. Что чем проверяется

- pytest: `plain_lines` (сценарии «Текст статьи в поисковом индексе без разметки»), `build_search_index`, маршрут и описание OpenAPI — на контенте из `ContentBuilder`.
- Vitest, модульные: `searchFold`, `affixFormula`, `search` — по сценариям specs/topic-search о вхождении, диакритике, формулах, словах запроса, порядке и строке результата.
- Vitest, компонентные: `SearchDialog` — роли, стрелки, Enter, указатель, `summary`; `TopicSearch` с `SearchLauncher` в `Layout` — открытие кнопкой и сочетанием, состояния, переход по адресу; `TopicPage` — прокрутка к блоку. Сеть подменяет msw, индекс для тестов лежит в `src/test/fixtures.ts`. В `src/test/setup.ts` возвращается заглушка `scrollIntoView`.
- В браузере: удержание фокуса, Escape, затемнение, окно поиска поверх окна темы, перехват Ctrl+K, прокрутка списка под указателем, вид на ширине 375 пикселей, время поиска на настоящем индексе.

## Risks / Trade-offs

- [Свёртка объединяет ı и i, o и ö] → запрос с диакритикой находит и слова без неё. Для 227 тем шум невелик; если мешает — точные совпадения поднимаются выше отдельным изменением.
- [Короткий запрос совпадает с вариантами многих формул: `a` равен варианту `-(y)A` и входит в десятки других] → ступень 1 ставит точные варианты первыми, а список обрезан до двадцати тем с общим числом найденных.
- [Правило узнавания формулы примет за формулу турецкое слово с заглавной буквой в середине] → в названиях таких слов нет; модульный тест прогоняет узнавание по названиям из тестового индекса, а на настоящем контенте это проверяется в браузере.
- [Произвольная словоформа, которой нет в примерах, не находится] → это граница поиска по вхождению; подсказка при пустом запросе называет то, что искать можно. Разбор словоформы — отдельное изменение с анализатором на сервере.
- [Индекс растёт до 1,2 МБ] → он грузится один раз за сеанс и только при открытии окна; при переносе справочника с локальной машины на сервер понадобится сжатие ответов.
- [Браузер или расширение не отдаёт странице Ctrl+K] → кнопка в шапке делает то же самое.
- [jsdom не умеет ни модальных окон, ни прокрутки] → заглушки проверяют связку, поведение браузера проверяется в запущенном приложении (tasks.md, группа 6).
- [`<a role="option">` теряет для программы чтения с экрана роль ссылки] → внутри списка вариантов это ожидаемо: выбор делается Enter в поле, а ссылкой строка остаётся для мыши и новой вкладки.
